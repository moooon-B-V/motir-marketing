One operation, EXPANDED — the state the renderer builds to

The content column only. Section order is FIXED: scope → request → body → example → responses → response schema.
POST /api/v1/projects/{projectKey}/work-items work_item:edit

Create a work item

Create a work item in a project. The parent, if given, is named by its key and must be a kind-legal parent in the same project.

Request

Parameter In Description
projectKey
string · required 		path The project’s key — the prefix of its work items’ keys, e.g. MOTIR.

Request body

Property Type Description
kind
required 		string
epic · story · task · subtask · bug 		The work item kind.
title
required 		string The work item title, one line.
parentKey
optional 		string | null A kind-legal parent in the same project.
storyPoints
optional 		number | null The agile sizing number.
targetRepos
optional 		string[] Every repository this item ships in, ordered.

Example

curl

curl -X POST 'https://app.motir.co/api/v1/projects/{projectKey}/work-items' \
  -H 'Authorization: Bearer $MOTIR_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"kind":"epic","title":"<title>"}'

Responses

Status Condition
201 The created work item.
403 The token may not edit work items in this project.
422 The body did not validate.
500 An unexpected error.

Response schema

Property Type Description
key
required 		string The identifier, e.g. MOTIR-42.
status
required 		string The workflow status key.
Why the order is a SPEC and not a layout preference. A reader who has read one operation must be able to SKIM the next, which only works if the next is laid out identically. The order, the verb chip’s hue-in-the-background recipe and the three-tint status rule are kept from motir-core/design/api-docs/design-notes.md, the asset the deleted renderer was drawn to. What is NOT kept is that asset’s shell — see § “What was kept, and what was deliberately not”.

Sandbox

A sandbox is a container you start on your own machine, holding a coding agent, the Motir CLI and your checkouts — and nothing else.

Start one

run

docker run -it --name motir-sandbox \
  -v "$PWD:/workspace" \
  -v "$HOME/.claude:/home/node/.claude:ro" \
  ghcr.io/moooon-b-v/motir-sandbox:claude
No find box on a prose page. The control filters OPERATIONS, and a filter over an empty set is a control describing nothing. What decides it is the ROUTE PREFIX, not the page — tiers two and three render if and only if the route is /docs/api or below, so a page added anywhere else cannot acquire the operation list by accident.

1 The filter narrows IN PLACE

Typing filters the operation rows and KEEPS the group headings, so a reader never loses where they are. The count line reports the narrowed set against the whole — a filter that hides its own selectivity is how a reader concludes an operation does not exist.

2 Two interactions to any operation

Filter, then click the row — or click a row directly from the resting rail. Scrolling is not one of them. The row carries the verb chip AND the path because the same path appears under four verbs, and a list of paths alone is ambiguous exactly where the reader is looking hardest.

3 The ACCESS PATH — the door in

A reader arrives from the top bar’s Docs item (panel 1, marked current), lands on the overview, and every page from there carries the rail — so the reference is one click from any documentation page and two from anywhere on the site. The rail row for the page you are on carries aria-current="page" and the active treatment; that is the “you are here”, and it is the same signal at every tier.

The rail is the answer, and the alternatives were weighed. An in-page index would put a fiftieth block of links at the top of the page a reader is trying to get out of, and it disappears the moment they scroll. A filter with no rail leaves nothing to read when the box is empty, which is the resting state. The rail is both — a persistent table of contents that a filter narrows — and it is what the surface had before the move, so it also restores something rather than inventing it.

API reference

The API reference is temporarily unreachable.

This page renders the OpenAPI document Motir publishes and keeps no copy of it, so there is nothing to show you in the meantime. Read app.motir.co/api/openapi/v1.json directly, or try again in a moment.

The rail survives; only the operation tier does not. The page links are this repository’s own and are always renderable, so a reader who meets this state can still leave for the CLI or sandbox pages. Blanking the whole rail would strand them on the one page that failed.
