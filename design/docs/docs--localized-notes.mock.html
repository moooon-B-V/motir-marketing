A delta on design/docs/docs.mock.html: only what the story adds to a translated page changes. Two notices — the generated-reference note (a permanent explanation: these descriptions are generated, so they stay English) and the being-updated note (a temporary state: this page is shown in English while its translation is made current) — their placement, their English source text, the lang rule for the English regions inside a translated page, and the three decisions the code items build to exactly: panel D (stale or missing), E (both would apply) and F (a tool summary that falls back). The rail, the page column, the operation and the command list are the base asset’s and the shipped components’; the header’s language control is the shipped LanguageSwitcher.

Why no marker is not a silent defect. (1) The fallback is a whole sentence in English, never a fragment inside a Korean one, which is the only mixing the requirement forbids. (2) It is never stale: the English shown is the current English, so a reader is not handed an outdated instruction. (3) It is programmatically honest: the summary element carries lang="en", so a screen reader switches voice and the font falls back to Latin faces. (4) A visible marker would need new catalogue data per tool, and motir-core’s per-locale catalogue is specified to keep the unlocalized shape; the page would also flicker with a page-level note on every English edit. (5) The reader of a tool reference already reads tool names, scopes and schemas in English. The dashed tag is annotation.
