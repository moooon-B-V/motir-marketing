What Motir is

Describe what you want to build in chat, and Motir drafts the issue tree. Read it, change it, approve it — then hosted agents execute it, card by card, and the pull requests come back to the board they came from.

How it is built

  • Open core: the whole project-management tool is GPL-3.0.
  • The AI planning layer is a hosted service the tool calls.
  • Agents do design, decisions and content — not only code.

Where to start

The Roadmap tab is what we are building next, ordered by how many people asked for it. Anything on it started as a request.

The affordance table — AMENDMENT 4 §D, row by row

Every row of the decision, and where in this asset it is drawn. A row this asset does not draw would be a row nobody built.
# affordance mechanism what is DRAWN, and where
1 account menu / sign-in dialog ABSENT Panels 1–12, the chrome: one plain Sign in link to app.motir.co and no account menu, identical in every panel. There is no modal anywhere in this asset.
2 follow HAND-OFF Panel 1's act rail — a primary button with the ↗ affix, href to /act?intent=follow&subject=MOTIR&return=…. Panel 14 draws the return.
3 subscribe ANONYMOUS-DIRECT Panel 1 — a real email field and button, on this page, no ↗. The only write drawn as staying here.
4 roadmap vote / request upvote HAND-OFF Panel 5's per-card vote pills and Panel 8's sidebar control. The COUNT renders anonymously; casting one leaves.
5 request comment HAND-OFF Panel 8 — the thread renders in full; the composer is replaced by the hand-off block, which says where it goes and that you come back.
6 submit a feature request HAND-OFF Panel 9 — title and duplicate step happen here, the submit is the hand-off. ⚠️ Because the intake has ALWAYS been session-gated: AMENDMENT 4 §A, MOTIR-4166.
7 in-place overview editing ABSENT Nowhere in this asset, deliberately. Panel 1's Overview has no edit affordance and no hover state that implies one. The author edits in the application.
8 viewer-awareness on the reads ALWAYS ANONYMOUS Every panel is the anonymous projection, and there is no second variant, because there cannot be one. Panel 8's callout states the cost and the gain.

The ACCESS PATH — how a visitor reaches this surface at all

Drawn as doors rather than described: three that lead in, one redirect, and one that deliberately does not exist.
door where it is lands on
/explore — the directory Every project square on motir.co/explore links href="/p/<identifier>", and does so TODAY, in production. Panel 1
A shared link The URL a customer sends their own users. It is the reason the canonical, og:url and JSON-LD @id must all name motir.co. Panel 1, or any deep link
A changelog feed item Each Atom entry's link is motir.co/p/<id>/items/<key> — a feed reader opens the item detail, not the project. Panel 7
app.motir.co/p/* A 308 from the application host, path preserved, once the cutover configures the public origin. Includes changelog.xml, which is in people's readers. the same path here
The chrome's nav ⚠️ NOT a door. /p/* has no nav entry and takes none: it is a tenant's page, not a section of this site. No nav item is current in any panel above. —

The window this story closes. Every square on /explore already links here and both hosts answer 404 today. The directory is live and points at nothing.
