motir.co landing — three entry doors, one idea box

The public front door for all three of Motir's first-time journeys, drawn for the standalone motir-marketing repo. It opens on a SYMMETRIC FORK: start something new and I have an existing project as two CO-EQUAL doors — same card, same accent border, same elevation, same heading, side by side, no OR between them. It then adds Start free — project management only as a genuinely tertiary door (door 3): a nav entry plus a single line under the hero, never a third card. Every door is a cross-origin hand-off into app.motir.co; this site draws no connect, import-source or chat UI of its own — those are owned by 7.15 / 7.17 / 7.3. The hero deliberately continues the shipped /onboarding entrance's exact vocabulary (Sparkles chip on --el-tint-lavender, serif headline, idea Card + textarea + ArrowRight primary Button) so a visitor who types here and lands there does not see two products. Copy shown is placeholder at the specified register — the final words are MOTIR-1144's.

One loop, three pieces

Motir is not a planner bolted onto a project-management tool. Planning feeds the board, and the board feeds the agents that do the work.

01

AI planning

Describe an idea in your own words. Motir asks the follow-up questions, then drafts an epic → story → task tree you read and edit before a line is written.

02

Project management

Real project management underneath: boards, sprints, a backlog, estimates, dependencies and blocked-by views, comments, search and reports. Usable on its own, with no AI at all.

03

Agent orchestration

Hand a card to an agent and it takes over the work — design, decisions, content, tests, code — and reports back on the board. Bring your own agent, or use a Motir-hosted one.

Open core — Motir is yours, GPL-3.0

The whole project-management layer is open source and self-hostable: work items, boards, sprints, collaboration, search, reporting and admin. The AI planning and agent layers are the commercial part. Read the source →

Door 1 — the idea box's four states

the submit is a CROSS-ORIGIN POST, so the failure state is drawn rather than left to be improvised: a hero that only draws the happy path loses the visitor's idea the first time the network blinks.
A · empty (rest) — and the focus ring
0 / 2000

The textarea holds focus on load; the visible ring is a 2 px --el-accent-on-surface outline at 2 px offset (6.57:1 light / 6.11:1 dark — 4.67:1 on 0.1.0, over WCAG 1.4.11's 3:1 either way). The counter is present but visibility: hidden, so revealing it never reflows the footer. Submit is ENABLED on an empty idea — the box is a head-start, not a gate, exactly as the /onboarding entrance decided.

B · typing
203 / 2000

The counter appears on first keystroke. The 2000 cap is not decorative: motir-core's MAX_PENDING_IDEA_LENGTH is 2000 and normalizePendingIdea() TRUNCATES past it — so a visitor who pastes 4000 characters silently loses half unless the bound is visible here. The textarea grows to a max height and then scrolls; it never pushes the CTA off screen.

C · submitting
203 / 2000

The button label CHANGES rather than only spinning — state is never carried by colour or motion alone, and a reduced-motion visitor sees a static glyph plus the word. aria-busy on the control and the textarea disabled, so a second submit cannot double-POST the draft.

D · submit failed (the cross-origin POST did not land)
We couldn't hand your idea over. Your text is still here — nothing was lost. Try again Continue without it
203 / 2000

The typed idea is never cleared. The banner is role="alert", an --el-danger hairline over --el-danger-surface with --el-danger-on-surface ink (5.77:1 light / 4.75:1 dark, re-measured on the pinned 0.1.1), and it carries an icon as well as the colour. Two exits: retry, or continue to sign-up without the hand-off — the visitor is never stranded on a dead button.

Dark theme — the same surface, no second design

every colour is the same token resolving to its Tier-1 dark value. The constraint this panel used to encode — no accent-coloured TEXT on the top bar, because --el-accent-on-surface on --el-surface-soft measured 4.41:1 in dark — is RETIRED: on the pinned 0.1.1 that pair is 5.76:1 (MOTIR-3874). Nothing on THIS page changes, because motir.co is the root and no nav item here is ever current; the bar's nav is --el-text-secondary (6.94:1) and the CTA is a filled Button (white on --el-accent, 4.99:1). The current-page treatment the constraint used to shape lives in design-showcase.mock.html.

The three doors — the routing contract MOTIR-1152 builds to

every door leaves motir.co. SHIPPED means the receiving half exists on motir-core's origin/main today; NOT READ YET means the parameter is specified here and nothing in motir-core reads it — see the notes' ACCESS PATH section for the fallback.
PRIMARY 1 · Start something new Starting fresh, wants AI planning. The LEFT door of the fork. POST the idea to the pre-auth draft receiver (MOTIR-1458), then https://app.motir.co/sign-in?draft=<id> SHIPPED
→ the /onboarding entrance pre-fills its CARRIED panel (MOTIR-1462).
PRIMARY 2 · I have an existing project Already has a codebase, or work items in Jira, Linear or Plane. The RIGHT door of the fork, drawing its three sources. https://app.motir.co/sign-in?intent=import NOT READ YET
→ the /onboarding entrance's EXISTING branch → 7.15 / 7.17.
TERTIARY 3 · Start free — project management only Wants the PM tool, no AI planning. A nav entry + one line under the hero. https://app.motir.co/sign-up?intent=tracker NOT READ YET
→ the 8.2 team first-run (MOTIR-655).
