Sentry を Motir のプロジェクトに接続すると、サービスがすでに報告しているエラーが、そのプロジェクトのボードにバグの作業項目として届きます。ほかの作業と同様に、計画され、担当者が割り当てられ、完了まで進められます。バグを修正すれば流れが完結し、Motir が Sentry 側のエラーを解決済みにします。

## できること {#what-it-does}

- **新しいエラーごとにバグが 1 件作られます。** Motir は、選択した Sentry プロジェクトを定期的に確認します。初めて見るエラーは、プロジェクトのバグの登録先に `bug` の作業項目として登録され、エラーの原因箇所、レベル、Sentry へのリンクが付きます。
- **再発したエラーは同じバグを更新します。** エラーが再び発生すると、既存のバグが更新されます。重複して登録されることはありません。
- **Motir で完了すると、Sentry で解決済みになります。** バグが完了ステータスになると、Motir が Sentry 側のエラーを解決済みにします。
- **Sentry の担当者がエラーに引き継がれます。** Sentry でエラーが誰かに割り当てられていて、その人が Motir ワークスペースのメンバーである場合（メールアドレスで照合します）、バグはその人に割り当てられます。

どちらの方向の連携も、監視中のプロジェクトごとにオフにできます。[設定](#settings)をご覧ください。

## 始める前に {#before-you-start}

- Motir で、プロジェクトの連携を管理する権限が必要です。権限がない場合、モニタリングのページに、誰に依頼すればよいかが表示されます。
- Sentry で、組織に連携をインストールする権限が必要です。通常はオーナーかマネージャーです。

## Sentry を接続する {#connect-sentry}

1. Motir でプロジェクトの設定を開き、_監視_ を選びます。
2. _Sentry を接続_ を選びます。Sentry に移動します。
3. Sentry で組織を選び、インストールを承認します。Sentry から Motir に戻り、_Sentry が接続されました。_ と表示されます。
4. _Sentry プロジェクトを選ぶ_ を選び、エラーをこのボードに届けたいプロジェクトを選択して確定します。確定するまでは何も届きません。

1 つの Motir プロジェクトから複数の Sentry プロジェクトを監視できます。後から _監視するプロジェクトを追加_ でさらに追加できます。

## 設定 {#settings}

監視中のプロジェクトごとに、独自の設定があります。

- **最小レベル** — このレベル以上のエラーだけが登録されます。既定は _すべてのレベル_ です。より低いレベルを選ぶと、そのプロジェクトの監視を開始した時点以降の過去のエラーも確認されます。
- **バグが完了したら Sentry で解決済みにする** — 既定ではオンです。オフにすると、バグが完了しても Sentry 側のエラーはそのままになります。
- **担当者を Sentry から取得** — 既定ではオンです。オフにすると、Sentry で行われた割り当てを無視します。

## 要求する権限 {#permissions-it-asks-for}

Motir は、これらの機能に必要な最小限の権限だけを Sentry に要求し、それ以上は要求しません。

| Sentry のスコープ | Motir での用途                                                                                                                                       |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `org:read`        | 接続された組織を読み取り、監視するプロジェクトを選べるようにその一覧を取得し、接続がまだ有効かどうかを確認します。                                   |
| `project:read`    | 監視対象に選んだプロジェクトを読み取ります。                                                                                                         |
| `event:read`      | 監視中のプロジェクトの新しいエラー（タイトル、レベル、原因箇所、発生回数、最新のスタックフレーム、担当者）を読み取り、それぞれをバグとして届けます。 |
| `event:write`     | バグが完了したときに、Sentry 側のエラーを解決済みにします。それ以外は何も書き込みません。                                                            |

Sentry が付与したアクセス権は暗号化して保存され、ご自身を含め、誰にも表示されることはありません。

## 接続が「低下」と表示されるとき {#when-the-connection-shows-degraded}

_低下_ は、Motir が組織のエラーを読み取れなくなっていることを意味し、解消されるまで新しいエラーはボードに届きません。ページには _Sentry のメッセージ：_ の横に、Sentry 自身の言葉で理由が表示されます。

- まず _再確認_ を選んでください。Sentry 側の一時的な問題であれば、自然に解消されます。
- 低下したままの場合は、_再接続_ を選びます。連携がすでにインストールされていると Sentry に表示された場合は、Sentry の組織の連携設定で Motir をアンインストールしてから、もう一度 _再接続_ を選びます。監視中のプロジェクト、その設定、登録済みのバグはそのまま保持されます。

## 接続を解除する {#disconnect}

Sentry のプロジェクトの監視をやめるには、その行の _監視を停止_ を使います。最後の監視中プロジェクトを削除する操作が _Sentry の接続を解除_ です。この操作では、Motir が保存している組織へのアクセス権も削除され、再び監視するには Sentry を通じてもう一度接続する必要があります。

すでに登録されたバグは、通常の作業項目としてボードに残ります。接続を解除しても、Sentry 側は何も変更されません。Sentry 側でもアクセス権を取り消すには、Sentry の組織の連携設定で Motir をアンインストールしてください。
