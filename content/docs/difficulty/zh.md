任务、子任务或缺陷可以带有一个 **难度**：它表示这项工作需要多少推理，而不是它有多少工作量。故事点和预估工时衡量的是规模。难度说明的是把这项工作做对有多难，因此一处只有一行的锁顺序改动可以是 `high`，而一次大规模的机械式重命名则是 `trivial`。

Motir 会在交给你的智能体的提示词中写明工作项的难度。Motir 不会替你选择模型：请根据下面的等级，决定每个工作项用哪个模型运行。篇章和故事不带难度。

## 四个等级 {#the-four-levels}

- **`trivial`**——机械性的工作，规格明确，不需要任何判断。这项改动已由工作项完整描述。例如：重命名、文案修改、切换一个配置、升级一个版本号。
- **`low`**——遵循代码库中已有模式的常规工作。需要做一些阅读，但一旦找到，正确答案就很清楚。例如：通过现有表单增加一个新字段、与相邻端点形态一致的端点、有明确复现步骤且范围受限的缺陷。
- **`medium`**——有真实设计抉择的工作：涉及多个文件或服务、需要权衡取舍，或者规格留有解释空间。例如：横跨 API 与界面的功能、有调用方需要迁移的重构、原因尚未查明的缺陷。
- **`high`**——细微的失误代价高昂的工作：并发、安全、数据迁移、身份认证，或者没有先例可循的设计。例如：锁顺序、权限模型的变更、对线上数据的模式迁移、一个新的子系统。

未设置难度时，把该工作项当作 `medium` 对待。未设置意味着还没有人判断过它，这并不是把它交给最便宜模型的理由。

## 如何看这些数字 {#reading-the-numbers}

- **两项基准互相不一致，所以哪一项都不能单独决定。** SWE-bench Pro 覆盖的模型更多，但据知其公开任务中约有 30% 是有缺陷的。SWE-rebench 更难被刷分，这也是 DeepSeek V4 Pro 和 GPT-5.6 Luna 位于 `trivial` 的原因：它们在其全新任务上的得分都低了 15 到 19 分。
- **比较完成一个任务的成本，而不是每个 token 的价格。** 一个更便宜但失败后必须重新运行的模型，比一个第一次就成功的更强模型花得更多。GPT-5.6 Sol 和 Claude Sonnet 5 每个 token 的价格相同，但 Sol 完成了更多任务，单任务成本也更低。
- **运行失败时上调一个等级。** 如果某个工作项的检查失败或评审被拒绝，就在高一个等级的模型上重新运行它，而不是在原来的模型上。
- **确认你的数据可能流向哪里。** 并非每个提供商都能用于每个项目。各提供商如何对待发送给它的内容，见[模型提供商](/legal/model-providers)。
