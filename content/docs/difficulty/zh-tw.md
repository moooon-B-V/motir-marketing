工作、子工作或錯誤可以帶有一個 **難度**：它表示這項工作需要多少推理，而不是它有多少工作量。故事點數和預估工時衡量的是規模。難度說明的是把這項工作做對有多難，因此一處只有一行的鎖順序改動可以是 `high`，而一次大規模的機械式重新命名則是 `trivial`。

Motir 會在交給你的代理程式的提示中寫明工作項目的難度。Motir 不會替你選擇模型：請根據下面的等級，決定每個工作項目用哪個模型執行。史詩和使用者故事不帶難度。

## 四個等級 {#the-four-levels}

- **`trivial`**——機械性的工作，規格明確，不需要任何判斷。這項改動已由工作項目完整描述。例如：重新命名、文案修改、切換一個設定、升級一個版本號。
- **`low`**——遵循程式碼庫中已有模式的常規工作。需要做一些閱讀，但一旦找到，正確答案就很清楚。例如：透過現有表單增加一個新欄位、與相鄰端點形態一致的端點、有明確重現步驟且範圍受限的錯誤。
- **`medium`**——有真實設計抉擇的工作：涉及多個檔案或服務、需要權衡取捨，或者規格留有解釋空間。例如：橫跨 API 與介面的功能、有呼叫方需要遷移的重構、原因尚未查明的錯誤。
- **`high`**——細微的失誤代價高昂的工作：並行、安全、資料遷移、身份認證，或者沒有先例可循的設計。例如：鎖順序、權限模型的變更、對正式環境資料的模式遷移、一個新的子系統。

未設定難度時，把該工作項目當作 `medium` 對待。未設定意味著還沒有人判斷過它，這並不是把它交給最便宜模型的理由。

## 如何看這些數字 {#reading-the-numbers}

- **兩項基準互相不一致，所以哪一項都不能單獨決定。** SWE-bench Pro 覆蓋的模型更多，但據知其公開任務中約有 30% 是有錯誤的。SWE-rebench 更難被刷分，這也是 DeepSeek V4 Pro 和 GPT-5.6 Luna 位於 `trivial` 的原因：它們在其全新任務上的得分都低了 15 到 19 分。
- **比較完成一個任務的成本，而不是每個 token 的價格。** 一個更便宜但失敗後必須重新執行的模型，比一個第一次就成功的更強模型花得更多。GPT-5.6 Sol 和 Claude Sonnet 5 每個 token 的價格相同，但 Sol 完成了更多任務，單任務成本也更低。
- **執行失敗時上調一個等級。** 如果某個工作項目的檢查失敗或審查被拒絕，就在高一個等級的模型上重新執行它，而不是在原來的模型上。
- **確認你的資料可能流向哪裡。** 並非每個供應商都能用於每個專案。各供應商如何對待傳送給它的內容，見[模型供應商](/legal/model-providers)。
