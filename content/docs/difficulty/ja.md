タスク、サブタスク、バグには**難易度**を設定できます。難易度とは、作業の量ではなく、その作業にどれだけの思考が求められるかを表すものです。ストーリーポイントと見積もりは規模を測ります。難易度は、正しく仕上げることがどれだけ難しいかを表します。そのため、ロック順序を 1 行変更するだけの作業が `high` になることもあれば、大規模でも機械的な名前変更が `trivial` になることもあります。

Motir は、エージェントに渡すプロンプトに作業項目の難易度を記載します。Motir がモデルを選ぶことはありません。以下のレベルを参考に、各作業項目をどのモデルで実行するかを決めてください。エピックとストーリーには難易度を設定しません。

## 4 つのレベル {#the-four-levels}

- **`trivial`** — 仕様が明確で、判断を要しない機械的な作業です。変更内容が作業項目に完全に記述されています。例: 名前の変更、文言の変更、設定の切り替え、バージョンの更新。
- **`low`** — コードベースにすでにあるパターンに従う定型的な作業です。多少のコード読解は必要ですが、見つかれば正解は明らかです。例: 既存のフォームに新しいフィールドを通す、近くの実装と同じ形のエンドポイント、再現手順が明確で影響範囲が限られたバグ。
- **`medium`** — 設計上の判断が実際に必要な作業です。複数のファイルやサービスにまたがる、トレードオフを検討する、解釈の余地がある仕様、などが該当します。例: API とインターフェースにまたがる機能、呼び出し元の移行を伴うリファクタリング、原因がまだわからないバグ。
- **`high`** — 小さなミスが大きなコストにつながる作業です。並行処理、セキュリティ、データ移行、認証、前例のない設計などが該当します。例: ロック順序、権限モデルの変更、本番データに対するスキーマ移行、新しいサブシステム。

難易度が設定されていない場合は、その作業項目を `medium` として扱ってください。未設定とは、まだ誰も判断していないという意味であり、最も安価なモデルに回してよいという意味ではありません。

## 数値の読み方 {#reading-the-numbers}

- **2 つのベンチマークは一致しないため、どちらか一方だけで判断しないでください。** SWE-bench Pro は対象モデルが多い一方、公開タスクの約 30% に不備があることが知られています。SWE-rebench は不正に有利にしにくく、DeepSeek V4 Pro と GPT-5.6 Luna が `trivial` に入っているのはそのためです。どちらも、新しいタスクでのスコアが 15〜19 ポイント低くなります。
- **トークンあたりの価格ではなく、完了したタスクあたりのコストで比較してください。** 安価なモデルが失敗して再実行が必要になると、1 回で成功する高性能なモデルよりコストが高くつきます。GPT-5.6 Sol と Claude Sonnet 5 はトークンあたりの価格が同じですが、Sol のほうがより多くのタスクを完了し、タスクあたりのコストも低くなりました。
- **実行が失敗したら、1 つ上のレベルに上げてください。** 作業項目のチェックが失敗したり、レビューが差し戻されたりした場合は、同じモデルではなく、1 つ上のレベルのモデルで再実行します。
- **データの送信先を確認してください。** すべてのプロバイダーをすべてのプロジェクトで使えるわけではありません。各プロバイダーが送信された内容をどう扱うかについては、[モデルプロバイダー](/legal/model-providers)をご覧ください。
