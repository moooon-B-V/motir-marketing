公開読み取り API は匿名で利用できます。すべての読み取りエンドポイントは、サインインなしでプロジェクトのデータを返し、そのおかげでプロジェクトスクエアはログアウト中の訪問者にも動作します。アカウントに紐づくものはすべて、トークンが必要です。以下の 5 つの手順は、それぞれ目に見える結果で終わります。

すべてのパスは、このビルドが指すアプリケーションホストからの相対パスで、以下に示します。リクエストはこのホストに対して書かれているので、そのままコピーして使えます。

{{slot:app-host}}

## 1. トークンを発行する {#mint-a-token}

「設定 → アカウント → トークン」でパーソナルアクセストークンを発行し、紐付けるワークスペースを選んで、必要な権限を付与します。権限の名前は、「ロールと権限」画面に表示されるものと同じ `resource:action` の形式です。その作業に足りる最も狭い権限だけを付与してください。付与はご自身のロールを狭めるだけで広げることはないため、トークンが、あなたにできないことをできるようになることはありません。

**シークレットが表示されるのは、トークンを作成したときの 1 回だけです。** そのときにコピーしてください。後から読み取る方法はなく、紛失したトークンは復元ではなく再発行します。

## 2. 最初の認証済み呼び出し {#first-call}

まず、この呼び出しを行ってください。トークンが誰のものか、どのワークスペースに紐付いているか、どの権限を持っているかが返ります。エンドポイントを試して拒否を集めなくても、ご自身の認証情報で何ができるかがわかります。

{{slot:first-call-response}}

トークンが存在しない、形式が正しくない、不明、失効済み、期限切れの場合は、すべて同じメッセージの同じ `401` が返ります。これは意図した仕様です。区別できるようにすると、「このシークレットは存在するか」に答えるオラクルとして、エンドポイントが悪用されてしまいます。

## 3. コレクションをページ送りする {#paginate}

コレクションはカーソル方式でページ分けされます。`limit` でページサイズを指定し（デフォルトは 50 で、それより大きい値は拒否されずに 100 に丸められます）、前回のレスポンスの `nextCursor` を `cursor` として送り返します。`nextCursor` が `null` なら最後のページです。

{{slot:paginate-first-response}}

{{slot:paginate-next-request}}

カーソルは不透明で、署名されています。解析したり、自分で作ったり、別のコレクションに持ち越したりしないでください。ほかの場所で発行されたカーソルは `422` になり、黙って誤ったページが返ることはありません。受け取ったものを、そのまま送り返してください。

驚かれやすい非対称性が 1 つあるので、出会う前に知っておく価値があります。一部のコレクションは `totalCount` も返しますが、ほとんどは意図的に返しません。コレクションの背後にある読み取りが、すでに上限付きの集計として総数を計算している場合は報告され、そうでない場合はこのフィールドは完全に省略されます。`null` でも `0` でもなく、存在しません。そのため、クライアントは常に「総数は約束されていない」ことと「総数がゼロである」ことを区別できます。

## 4. エラーを読む {#read-an-error}

すべての失敗は同じボディを返します。機械向けの `code` と、人間向けの `error` です。分岐には `code` を使ってください。これは安定していて、変更は破壊的変更にあたります。`error` は解析しないでください。ターミナルを読む開発者向けの文であり、自由に言い換えられます。

{{slot:error-404-response}}

`404` は、リソースが存在しないか、**または**トークンが紐付いているワークスペースの外にあることを意味します。意図的に同じ応答にしており、API を使って別のテナントのデータを列挙できないようにするためです。`403` は逆の種類の拒否です。トークンは有効ですが、付与された権限に、この操作に必要な権限が含まれていません。レスポンスにはそのキーが示されます。`422` は修正できるリクエストで、その `code` がどの部分かを示します。

**`500` は、`code` を持たない唯一の失敗です。** 想定外の障害には安定した契約がないため、ボディにはメッセージだけが入ります。これで分岐しないでください。

## 5. レスポンスヘッダーを読む {#rate-limits}

上限はトークン単位で、ヘッダーはすべてのレスポンスに付きます。成功、拒否、対応付けられたエラー、障害のいずれでも同じです。現在の状況を知るためにリクエストを送る必要はありません。直前のリクエストがすでに教えてくれています。

{{slot:response-headers}}

`429` のときは、`X-RateLimit-Reset` まで待機してから再試行してください。これは秒単位の Unix タイムスタンプです。`Retry-After` ヘッダーは意図的にありません。相対的な時間は転送中に古くなることがありますが、絶対的な時刻は古くならないからです。

`X-Request-Id` もすべてのレスポンスに付いています。特定の呼び出しについてお問い合わせいただく際には、これを添えてください。その呼び出しを特定できる唯一の識別子です。

`X-Motir-Api-Version` は、そのレスポンスを返した契約のバージョンです。Motir のリリース番号ではなく、`MAJOR.MINOR.PATCH` の形式で、仕様の `info.version` と同じものです。失敗を含む任意のレスポンスから読み取り、バージョンのずれを確認してください。知らないメジャーバージョンがあれば `/api/v2` が存在し、マイナーバージョンが上がっていれば契約が追加で拡張されたことを意味します。その場合もクライアントは正しく動作します。上のブロックにバージョンではなくプレースホルダーが表示されている場合は、このページを描画した時点で仕様に到達できなかったことを意味します。[API リファレンス](/docs/api)は、現在のバージョンをドキュメントから直接読み取ります。
