공개 읽기 API에는 버전이 있습니다. 계약 버전은 제공되는 OpenAPI 문서의 `info.version` 필드에 담기며, 클라이언트를 깨뜨리는 변경은 조용한 수정이 아니라 버전 증가로 이루어집니다.

## `v1`이 보장하는 것 {#the-guarantee}

`v1`이 유지되는 동안 경로는 바뀌지 않고, 오류 `code`의 의미도 바뀌지 않으며, 기존 조건의 상태도 바뀌지 않고, 필드의 유형이나 null 허용 여부도 바뀌지 않습니다. 이를 깨뜨리는 변경은 `v2`이며, `v1` 릴리스가 아닙니다.

### 공지 없이 `v1`에서 허용되는 변경 {#allowed-inside-v1}

- 새 엔드포인트.
- 새 선택적 쿼리 매개변수.
- 응답 객체의 새 필드.
- 새 응답 헤더.
- 열린 값으로 문서화된 필드의 새 값.
- 상향된 속도 제한 한도.

### 새 메이저 버전이 필요한 변경 {#needs-a-new-major}

- 필드 제거.
- 필드 이름 변경.
- 필드의 유형이나 null 허용 여부 변경.
- 오류 `code` 제거 또는 용도 변경.
- 기존 조건에 대한 기존 상태 변경.
- 제한 강화.
- 선택적 매개변수를 필수로 변경.

## 사용자의 몫 {#your-obligation}

**클라이언트는 알 수 없는 필드와 값을 반드시 허용해야 하며, 사람이 읽는 `error` 문장을 파싱해서는 안 됩니다.** 이것은 약속의 나머지 절반이며, 이것이 없으면 위의 보장은 성립하지 않습니다. 인식하지 못하는 필드를 거부하는 클라이언트는 이 페이지에서 안전하다고 한 변경에도 깨지고, `error`를 파싱하는 클라이언트는 문장이 다시 쓰이면 깨집니다. `code`로 분기하고 모르는 것은 무시하면, 추가적인 변경은 모두 부담 없이 받아들일 수 있습니다.

## 지원 중단 {#deprecation}

지원 중단된 작업이나 필드는 **사양에** `deprecated: true`로 표시되며, 설명에 이유와 대체 수단이 함께 적힙니다. 사양을 공지 채널로 쓰는 이유는 모든 클라이언트가 이미 읽는 유일한 산출물이기 때문입니다. 따라서 코드 생성기가 블로그 글을 본 사람이 없어도 지원 중단을 알려 줍니다.

이전 동작은 공지된 기간 동안 계속 작동합니다. 필드가 예고 없이 제거되는 일은 없습니다.

## `v2`가 나오는 방식 {#how-v2-arrives}

다시 쓰는 것이 아니라, 두 번째 경로의 두 번째 문서로 `v1`과 나란히 제공됩니다. `v1`은 `v2`가 출시되는 날 멈추지 않으며, `v1`의 지원 중단 역시 같은 기간 규칙을 따르는 공지입니다.

사양의 `info.version`은 앱의 릴리스 번호가 아니라 API 계약의 버전입니다. 메이저는 경로 버전이고, 마이너는 위 목록의 추가적 변경이 있을 때 증가하며, 패치는 문서만 바로잡을 때 증가합니다. 어떤 응답에서든 `X-Motir-Api-Version`으로 읽을 수 있으며, 위치는 [시작하기](/docs/api/getting-started)에 나와 있습니다.

이 페이지는 공개된 약속입니다. 이 페이지의 바탕이 된 내부 기록은 [API 결정 기록](https://github.com/moooon-B-V/motir-core/blob/main/docs/decisions/public-api-conventions.md) §8입니다.
