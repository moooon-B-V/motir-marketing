公开读取 API 是有版本的。契约版本记录在所提供的 OpenAPI 文档的 `info.version` 字段中，会破坏客户端的更改是一次版本升级，而不是悄悄的修改。

## `v1` 保证什么 {#the-guarantee}

在 `v1` 存续期间，它的路径不会移动，错误 `code` 的含义不会改变，既有条件的状态码不会改变，字段的类型或可空性也不会改变。任何会破坏这些的更改都属于 `v2`，而不是 `v1` 的发布。

### `v1` 内允许、无需通知的更改 {#allowed-inside-v1}

- 新增端点。
- 新增可选的查询参数。
- 在响应对象上新增字段。
- 新增响应头。
- 在文档中标明为开放式的字段上新增取值。
- 提高速率限制额度。

### 需要新的主版本的更改 {#needs-a-new-major}

- 移除字段。
- 重命名字段。
- 更改字段的类型或可空性。
- 移除错误 `code`，或为其赋予新用途。
- 更改既有条件对应的既有状态码。
- 收紧限制。
- 把可选参数变为必填。

## 你这一方的责任 {#your-obligation}

**客户端必须容忍未知的字段和未知的取值，并且不得解析面向人的 `error` 句子。** 这是承诺的另一半，没有它，上面的保证就不成立：拒绝接受自己不认识的字段的客户端，会在本页称为安全的更改上出错；解析 `error` 的客户端，会在句子被改写时出错。请根据 `code` 分支处理，忽略你不认识的内容，这样每一次增量更改对你来说都不会有任何代价。

## 弃用 {#deprecation}

被弃用的操作或字段会 **在规范中** 标记为 `deprecated: true`，并在其描述中给出原因和替代方案。规范是公告渠道，因为它是每个客户端都已经在读的唯一产物——这样代码生成器就能直接呈现弃用信息，而不必有人事先看过某篇博客文章。

旧的行为会在公告的期限内继续有效。字段绝不会被突然移除。

## `v2` 将如何到来 {#how-v2-arrives}

它会作为第二个文档出现在第二个路径上，与 `v1` 并行提供——而不是对它的重写。`v1` 不会在 `v2` 发布的那天停止工作，弃用 `v1` 本身也是一项遵循同一期限的公告。

规范中的 `info.version` 是 API 契约的版本，而不是应用的发布版本号：它的主版本就是路径版本，次版本在上面列出的增量更改发生时递增，补丁版本在仅修订文档时递增。可以从任何响应中把它读作 `X-Motir-Api-Version`——[快速开始](/docs/api/getting-started)说明了在哪里看。

本页是已发布的承诺。它所依据的内部记录是 [API 决策记录](https://github.com/moooon-B-V/motir-core/blob/main/docs/decisions/public-api-conventions.md)，第 8 节。
