Motir 的技能讓你已經在用的代理程式來運轉你的 Motir 專案。說 `motir run`，它就會領取下一個就緒的工作項目，建置它，並開啟一個關聯的提取要求。說 `motir log bug`，它會核實該錯誤，並把它提交到合適的位置。說 `motir mark`，在你完成一個手動工作項目之後，它會將其關閉。說 `motir guide`，它會一步一步帶你完成一個手動工作項目。

它們是普通的 [Agent Skills](https://agentskills.io)：每個技能一個資料夾，各含一個 `SKILL.md`，釋出在 [{{value:skillsRepo}}]({{value:repoUrl}})。本頁的每條指令安裝的都是版本 [`{{value:releaseTag}}`]({{value:releaseUrl}})。

## 開始之前 {#before}

這些技能透過 Motir 的 MCP 伺服器與 Motir 通訊。在 Claude Code 中，外掛會替你連線它：你在瀏覽器中用 Motir 帳戶登入，不需要權杖。其他所有代理程式都需要先連線這個伺服器——需要一個 Motir 專案、一個個人存取權杖，以及 [{{value:mcpPage}}](/docs/mcp) 指南中針對你的代理程式的設定；如果無法使用瀏覽器登入，該指南也介紹了 Claude Code 中的權杖路線。使用預設權限的權杖，就可以完成這些技能所做的一切。你還需要 `git`，以及用於開啟或讀取提取要求的技能所需的 GitHub CLI（`gh`）。

## 安裝 {#install}

選擇你的代理程式。每一節都會為你機器上的每個專案安裝該版本中的每個技能。終端機指令適用於 macOS 和 Linux：它們取得該版本，把技能資料夾複製到該代理程式讀取的資料夾中，並刪除下載的內容。

### Claude Code {#claude-code}

該儲存庫同時也是一個 Claude Code 外掛市場。按版本標籤新增它，然後安裝外掛。一次安裝即可獲得技能、Motir 的 MCP 伺服器和 CLI 的執行器，並且無需權杖即可連線 Motir。

- **七個技能。** 該版本中的每個技能，都列在外掛名稱之下。
- **Motir MCP 伺服器。** Claude Code 會在首次使用時於瀏覽器中登入它：執行 `/mcp`，選擇 `motir` 並選擇 _Authenticate_，然後選擇工作區，並在 Motir 的授權頁面上核准。無需建立或貼上權杖。 [將 Motir 新增到 Claude](/docs/mcp#claude)

## 使用 {#use}

把 **你可以說** 下面的內容輸入到你的代理程式中。把 `ACME-12` 換成你自己專案中某個工作項目的鍵。

### `motir-run` {#motir-run}

**你可以說**

- `motir run`
- `motir run ACME-12`
- `motir next`

**會發生什麼**

領取你專案中下一個就緒的工作項目，或你指定的那個，並建置它。它先收尾此前那些提取要求已經合併的執行，然後領取該工作項目，在屬於它自己的分支上建置，開啟一個提取要求，並把該提取要求關聯到工作項目。若指定的是一個使用者故事，且其子項都沒有自己的子項，它會執行整個使用者故事：每個儲存庫一個分支、一個提取要求，每個子項一次提交。`motir next` 在領取之後就會停下並輸出提示，由你自己交給某個代理程式。決策工作項目是唯一的例外：它會撰寫決策頁面並發布，等待你核准，不產生分支，也不產生提取要求。

**你在 Motir 中看到什麼**

該工作項目會被分配給你並變為進行中，提取要求開啟後變為已實作。它的頁面會顯示提取要求和「如何測試」部分。CI 透過時由 Motir 把它移到審查中，提取要求合併時移到已完成；技能自己從不做這兩件事。

### `motir-fix` {#motir-fix}

**你可以說**

- `motir fix ACME-12`

**會發生什麼**

在開啟提取要求的那次執行結束之後，修復一個紅色的提取要求：它的檢查失敗了、合併佇列把它踢了出來，或者審查者把使用者故事的驗收影片以「重新執行」退了回來。它首先領取這次修復，這樣別人就不會在它之上推送。然後它在工作項目每個提取要求已有的分支上修復，絕不新增分支：合併基礎分支，修復失敗的檢查所指出的故障，然後推送。它會一直進行到 CI 變綠，或已嘗試五次；在「重新執行」之後 CI 變綠時，它會重新錄製驗收影片。它絕不會開啟提取要求、合併提取要求，也不會更改工作項目的狀態。它不同於 `motir fix bugs`，後者處理你專案的錯誤資料夾：`motir fix ACME-12` 修復的是你指定的那一個工作項目的提取要求。

**你在 Motir 中看到什麼**

修復進行期間，工作項目的「開發」部分會說明它正在被修復，以及由誰修復。相同的提取要求會得到新的提交，一旦它們的檢查透過，Motir 會自動推進該工作項目。如果修復放棄了，工作項目會說明這一點，以及嘗試了多少次。

### `motir-continue` {#motir-continue}

**你可以說**

- `motir continue ACME-12`

**會發生什麼**

接續一個執行中途中斷的工作項目：筆電合上了、沙箱遺失了，或處理程序被終止了。該工作項目仍處於進行中，它的工作留在那次執行遺留的分支上。它首先領取這次接續，這樣別人就不會在同一個分支上工作。然後它在工作項目涉及的每個儲存庫中簽出那個分支，絕不新增分支，也絕不重置已有的內容，並從中斷的地方繼續工作。它的交付方式與全新的執行相同：每個儲存庫一個提取要求，關聯到該工作項目。如果工作項目已經有一個紅色的提取要求，請改用 `motir fix ACME-12`；對於還沒有人開始的工作項目，用 `motir run ACME-12`。

**你在 Motir 中看到什麼**

執行中斷的工作項目會在它的「開發」部分顯示「執行已中斷」，並附上可複製的 `motir continue` 指令。接續進行期間，該部分會說明它正在被接續，以及由誰接續。完成後，工作項目的推進方式與 `motir run` 之後完全相同：變為已實作，提取要求已關聯，並帶有「如何測試」部分。

### `motir-log-bug` {#motir-log-bug}

**你可以說**

- `motir log bug the export button does nothing on an empty board`

**會發生什麼**

把你輸入的內容當作需要核實的論斷。它先在程式碼中找出原因，查詢別人是否已經提交過相應的工作項目，如果發現該行為其實是正確的，就什麼都不提交。否則它會提交一個錯誤：放在它所阻擋的使用者故事之下；如果它不阻擋任何東西，則放在專案的錯誤資料夾中。

**你在 Motir 中看到什麼**

一個新的錯誤工作項目，包含原因、它在程式碼中的位置以及重現方式，並關聯到發現它的那個工作項目。如果它阻擋了你正在執行的工作項目，那個工作項目會變為已封鎖。

### `motir-mark` {#motir-mark}

**你可以說**

- `motir mark ACME-12 done`

**會發生什麼**

關閉一個任何提取要求都無法關閉的工作項目：手動的那種，例如建立帳戶、設定金鑰或更改某項設定。你說出這句話，就是在確認工作已經完成。如果工作項目帶有提取要求，它會拒絕，因為是該提取要求的合併來關閉它。

**你在 Motir 中看到什麼**

工作項目變為已完成，並附一條留言，記錄是你確認的。其父項的狀態會隨其子項而定。

### `motir-guide` {#motir-guide}

**你可以說**

- `motir guide ACME-12`
- `motir guide`

**會發生什麼**

一步一步帶你完成一個手動工作項目。指定一個，或者只說 `motir guide`，它就會接手你自己尚未完成的那個，否則接手下一個就緒的手動工作項目。它給你一個步驟，附帶該步驟的說明和任何要複製的指令，然後等待。你說「完成」，它就會檢查它在不做任何更改的前提下能檢查的內容，例如存取某個網址或執行唯讀指令，並告訴你它看到了什麼。檢查失敗的步驟不會被勾選；你會再次得到同一個步驟。你可以在任何一步停下，`motir guide` 會從你停下的地方繼續。如果工作項目還沒有步驟，它會根據描述提出一些步驟，並在把它們寫入工作項目之前徵求你的意見。如果某個步驟被發現有誤，它會提出更正，只有在你同意時才會更改該步驟或工作項目的文字。

**你在 Motir 中看到什麼**

工作項目被分配給你並變為進行中。它的待辦清單會在你完成每一步時勾選該步驟，並記錄是誰完成的。最後一步被勾選後，工作項目變為已完成，並附一條留言，概述每一步以及是如何確認的。

### `motir-fix-bugs` {#motir-fix-bugs}

**你可以說**

- `motir fix bugs`
- `motir fix bugs 3`

**會發生什麼**

逐個處理你專案錯誤資料夾中仍處於待辦的錯誤，一次一個，最舊的優先。錯誤資料夾內的子資料夾中的錯誤不處理。對每一個，它先確認該錯誤在你的預設分支上確實存在，然後給它恰好一種結果。能修復的錯誤會得到一個只修復該錯誤、不含其他內容的提取要求。依賴於另一個尚未完成的工作項目的錯誤，會關聯到那個工作項目，並移到同一個使用者故事之下。無法在這裡修復的錯誤會得到一條留言並被擱置：已經修復，並說明是什麼修復了它；無法重現，並說明它執行了什麼；或需要你來決定，並附上需要你回答的提問和它的建議。每種結果都會讓該錯誤離開待辦，所以執行會自行結束。加上一個數字，處理完那麼多個錯誤後它就會停止。它以一份報告收尾，其中先列出在等你的錯誤。

**你在 Motir 中看到什麼**

修復好的錯誤變為已實作，並關聯其提取要求，你合併後變為已完成。在等待其他工作的錯誤變為已封鎖，並帶有指向那個工作項目的「被封鎖」連結。已經修復的錯誤變為已完成。無法重現的錯誤，或需要你決定的錯誤，變為已封鎖。這些都附有一條寫明證據或提問的留言。回答該提問並把錯誤移回待辦，下一次執行就會接手它。

## 當工作項目有誤時 {#wrong}

有時一個工作項目無法按所寫的內容建置。它可能要求某個不存在的東西，需要一份沒有人畫過的設計，或者涉及兩個儲存庫。`motir-run` 不會猜著繞過去。它會把工作項目移到 **規劃中**，這樣其他執行就不會接手它，並請 Motir AI 規劃器規劃更正。然後停下。該計畫等待你在 Motir 中審查並核准，在你核准之前不會建置任何東西。

如果你的權杖無法使用 AI 規劃，或者你的 AI 額度用完了，它仍然會停下。它會在工作項目上留下一條包含完整更正的留言，並說明為什麼無法移交。
