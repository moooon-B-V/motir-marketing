Motir のスキルを使うと、普段お使いのエージェントで Motir のプロジェクトを進められます。`motir run` と言えば、次に着手できる作業項目を取り上げて実装し、リンクされたプルリクエストを開きます。`motir log bug` と言えば、不具合を確認して適切な場所に登録します。`motir mark` と言えば、手作業の作業項目をあなたが終えた時点でクローズします。`motir guide` と言えば、手作業の作業項目を 1 ステップずつ案内します。

これらは通常の [Agent Skills](https://agentskills.io) です。スキルごとに 1 つのフォルダーがあり、それぞれに `SKILL.md` が入っていて、[{{value:skillsRepo}}]({{value:repoUrl}}) で公開されています。このページのコマンドはすべて、リリース [`{{value:releaseTag}}`]({{value:releaseUrl}}) をインストールします。

## 始める前に {#before}

スキルは Motir の MCP サーバーを通じて Motir と通信します。Claude Code では、プラグインがこの接続を設定します。ブラウザーで Motir アカウントにサインインするだけで、トークンは不要です。それ以外のエージェントは、先にこのサーバーを接続しておく必要があります。必要なのは、Motir のプロジェクト、パーソナルアクセストークン、そしてお使いのエージェント向けのセットアップです。セットアップは [{{value:mcpPage}}](/docs/mcp) のガイドにあり、ブラウザーでのサインインを使えない場合の Claude Code でのトークンを使う方法も説明しています。デフォルトの権限のトークンで、これらのスキルが行うすべての操作ができます。また、`git` と、プルリクエストを開いたり読み取ったりするスキルのために GitHub CLI（`gh`）も必要です。

## インストール {#install}

お使いのエージェントを選んでください。各セクションでは、リリースに含まれるすべてのスキルを、お使いのマシン上のすべてのプロジェクトに向けてインストールします。ターミナルのコマンドは macOS と Linux 用です。リリースを取得し、スキルのフォルダーをそのエージェントが読み込むフォルダーにコピーして、ダウンロードしたファイルを削除します。

### Claude Code {#claude-code}

このリポジトリは Claude Code のプラグインマーケットプレイスでもあります。リリースタグを指定して追加し、プラグインをインストールしてください。1 回のインストールで、スキル、Motir の MCP サーバー、CLI を実行するランナーが入り、トークンなしで Motir に接続できます。

- **7 つのスキル。** リリースに含まれるすべてのスキルが、プラグイン名の下に一覧表示されます。
- **Motir MCP サーバー。** Claude Code は、初めて使うときにブラウザーでサインインします。`/mcp` を実行して `motir` を選び、_Authenticate_ を選んでから、ワークスペースを選び、Motir の同意画面で承認します。作成したり貼り付けたりするトークンはありません。[Claude に Motir を追加する](/docs/mcp#claude)
- **`motir` ランナー。** `npx` で、バージョンを固定した Motir CLI を実行するため、グローバルには何もインストールされません。Node.js 22 以降が必要で、CLI は `motir login` で自動的にサインインします。

## 使い方 {#use}

**言うこと**の下にあるものを、エージェントに入力してください。`ACME-12` は、ご自身のプロジェクトの作業項目のキーに置き換えます。

### `motir-run` {#motir-run}

**言うこと**

- `motir run`
- `motir run ACME-12`
- `motir next`

**何が起こるか**

プロジェクトで次に着手できる作業項目、またはあなたが指定した作業項目を取り上げて実装します。最初に、プルリクエストがマージされた過去の実行の後片付けを行い、次に作業項目を確保し、専用のブランチで実装して、プルリクエストを 1 つ開き、そのプルリクエストを作業項目にリンクします。子の作業項目が、さらに子を持たないストーリーを指定すると、ストーリー全体を実行します。リポジトリごとに 1 つのブランチと 1 つのプルリクエストを使い、子ごとに 1 つのコミットを作ります。`motir next` は確保の後で止まり、プロンプトを表示します。そのプロンプトを、ご自身でエージェントに渡します。決定の作業項目は唯一の例外です。決定ページを書き、承認のために公開します。ブランチもプルリクエストも作りません。

**Motir での見え方**

作業項目はあなたに割り当てられ、進行中になり、プルリクエストが開かれると実装済みになります。作業項目のページには、プルリクエストと「テスト方法」のセクションが表示されます。CI が通るとレビュー中に、プルリクエストがマージされると完了に、Motir が移します。スキル自身がそのどちらも行うことはありません。

### `motir-fix` {#motir-fix}

**言うこと**

- `motir fix ACME-12`

**何が起こるか**

プルリクエストを開いた実行が終わった後に、赤くなったプルリクエストを修復します。チェックが失敗した場合、マージキューに弾かれた場合、またはレビュアーがストーリーの受け入れ動画を「再実行」で差し戻した場合が対象です。最初に修復を確保するので、他の誰かが上書きしてプッシュすることはありません。続いて、作業項目の各プルリクエストを、すでにあるブランチ上で修正します。新しいブランチは作りません。ベースブランチをマージし、失敗したチェックが指摘した点を修正して、プッシュします。CI が通るか、5 回試すまで続けます。再実行の後で CI が通った場合は、受け入れ動画も録り直します。プルリクエストを開いたり、マージしたり、作業項目のステータスを移したりすることはありません。これは、プロジェクトの「バグ」フォルダーを順に処理する `motir fix bugs` とは別のものです。`motir fix ACME-12` は、指定した 1 つの作業項目のプルリクエストを修復します。

**Motir での見え方**

修復の実行中は、作業項目の「開発」セクションに、修復中であることと、その担当者が表示されます。同じプルリクエストに新しいコミットが追加され、チェックが通ると Motir が作業項目を自動的に先へ進めます。修復を断念した場合は、作業項目にその旨と試行回数が表示されます。

### `motir-continue` {#motir-continue}

**言うこと**

- `motir continue ACME-12`

**何が起こるか**

途中で実行が停止した作業項目を続行します。ノートパソコンを閉じた、サンドボックスが失われた、プロセスが強制終了されたといった場合です。作業項目は進行中のままで、作業内容はその実行が残したブランチにあります。最初に続行を確保するので、他の誰かが同じブランチで作業することはありません。続いて、作業項目が関わるすべてのリポジトリでそのブランチをチェックアウトします。新しいブランチは作らず、すでにある内容をリセットすることもなく、止まったところから作業を続けます。成果物の届け方は新規の実行と同じで、リポジトリごとに 1 つのプルリクエストを作り、作業項目にリンクします。作業項目にすでに赤いプルリクエストがある場合は、代わりに `motir fix ACME-12` を使ってください。まだ誰も着手していない作業項目には `motir run ACME-12` を使います。

**Motir での見え方**

実行が停止した作業項目には、「開発」セクションに「実行が停止」と表示され、コピー用の `motir continue` コマンドが示されます。続行の実行中は、そのセクションに続行中であることと、その担当者が表示されます。完了すると、作業項目は `motir run` の後と同じように先へ進みます。実装済みになり、プルリクエストがリンクされ、「テスト方法」のセクションが付きます。

### `motir-log-bug` {#motir-log-bug}

**言うこと**

- `motir log bug the export button does nothing on an empty board`

**何が起こるか**

入力された内容を、確認すべき主張として扱います。まずコードから原因を突き止め、すでに誰かが登録した作業項目がないかを調べます。挙動が正しいとわかった場合は、何も登録しません。そうでなければ、バグを 1 件登録します。そのバグが止めているストーリーの配下に登録します。何も止めていない場合は、プロジェクトの「バグ」フォルダーに登録します。

**Motir での見え方**

原因、コード上の場所、再現方法を記した新しいバグの作業項目が作られ、そのバグが見つかった作業項目にリンクされます。実行中の作業項目をそのバグが止めている場合は、その作業項目がブロック中になります。

### `motir-mark` {#motir-mark}

**言うこと**

- `motir mark ACME-12 done`

**何が起こるか**

プルリクエストではクローズできない作業項目をクローズします。アカウントの作成、シークレットの設定、設定の変更といった手作業の作業項目が対象です。この言葉を言うことが、作業が終わったというあなたの確認になります。プルリクエストがある作業項目は、そのプルリクエストのマージでクローズされるため、拒否されます。

**Motir での見え方**

作業項目は完了に移り、あなたが確認したことを記録したコメントが付きます。親のステータスは、子の状態に応じて決まります。

### `motir-guide` {#motir-guide}

**言うこと**

- `motir guide ACME-12`
- `motir guide`

**何が起こるか**

手作業の作業項目を、1 ステップずつ案内します。作業項目を指定するか、`motir guide` だけを言うと、あなた自身の未完了の作業項目を取り上げ、なければ次に着手できる手作業の作業項目を取り上げます。手順の説明と、コピーして使うコマンドがあればそれも添えて、1 つのステップを示し、待ちます。「完了」と言うと、何も変更せずに確認できることを確認します。たとえばアドレスを取得したり、読み取り専用のコマンドを実行したりして、確認できた内容を伝えます。確認に失敗したステップにはチェックを付けず、同じステップをもう一度示します。どのステップでも中断でき、`motir guide` を実行すると中断したところから再開します。作業項目にまだステップがない場合は、説明文から候補を提案し、作業項目に書き込む前にあなたに尋ねます。ステップが間違っているとわかったときは、修正案を示し、あなたが承諾した場合にのみ、そのステップや作業項目の文面を変更します。

**Motir での見え方**

作業項目はあなたに割り当てられ、進行中になります。ToDo リストでは、ステップを終えるたびにチェックが付き、誰が行ったかも記録されます。最後のステップにチェックが付くと、作業項目は完了に移り、各ステップの内容とその確認方法を要約したコメントが付きます。

### `motir-fix-bugs` {#motir-fix-bugs}

**言うこと**

- `motir fix bugs`
- `motir fix bugs 3`

**何が起こるか**

プロジェクトの「バグ」フォルダーにあるバグのうち、まだ未着手のものを、古いものから 1 件ずつ処理します。「バグ」フォルダーの中のフォルダーにあるバグは対象外です。各バグについて、まずデフォルトブランチで実際に発生することを確認し、そのうえでちょうど 1 つの結果を与えます。修正できるバグには、そのバグだけを修正する 1 つのプルリクエストが作られます。まだ終わっていない別の作業項目を待つバグは、その作業項目にリンクされ、同じストーリーの配下に移されます。ここでは修正できないバグにはコメントが付き、脇に置かれます。すでに修正済みの場合は修正した内容を、再現できない場合は実行した内容を、あなたの判断が必要な場合は質問と推奨案を添えます。どの結果でもバグは未着手でなくなるため、実行は自然に終わります。数字を付けると、その件数で止まります。最後に、あなたの対応を待っているバグを先頭に並べた報告を出力します。

**Motir での見え方**

修正されたバグは、プルリクエストがリンクされた状態で実装済みに移り、あなたがマージすると完了に移ります。他の作業を待つバグはブロック中に移り、その作業項目へのブロック元のリンクが付きます。すでに修正済みのバグは完了に移ります。再現できないバグや、あなたの判断が必要なバグはブロック中に移ります。いずれにも、証拠または質問を記したコメントが付きます。質問に答えてバグを未着手に戻すと、次の実行がそのバグを取り上げます。

## 作業項目に問題があるとき {#wrong}

作業項目が、書かれているとおりには実装できないことがあります。存在しないものを求めている、誰も描いていないデザインが必要、2 つのリポジトリにまたがっている、といった場合です。`motir-run` は推測で回避しようとはしません。その作業項目を**計画中**に移して、他の実行が取り上げないようにし、Motir の AI プランナーに修正の計画を依頼します。その後で停止します。計画はあなたが Motir でレビューして承認するのを待ち、承認するまで何も実装されません。

お使いのトークンで AI による計画を利用できない場合や、AI クレジットが尽きている場合も、停止します。その場合は、作業項目に修正内容の全体と、引き渡せなかった理由をコメントとして残します。

## 更新 {#updating}

新しいリリースには新しいタグが付き、このページはそのタグに移ります。コピーでインストールした場合は、お使いのエージェントのインストール手順をもう一度実行してください。スキルのフォルダーがその場で上書きされます。Claude Code では、マーケットプレイスを別のタグで追加し直すことはできないため、いったん削除し、新しいタグで追加して、プラグインをもう一度インストールしてください。
