Motir 的技能让你已经在用的智能体来运转你的 Motir 项目。说 `motir run`，它就会领取下一个就绪的工作项，构建它，并打开一个关联的拉取请求。说 `motir log bug`，它会核实该缺陷，并把它提交到合适的位置。说 `motir mark`，在你完成一个手动工作项之后，它会将其关闭。说 `motir guide`，它会一步一步带你完成一个手动工作项。

它们是普通的 [Agent Skills](https://agentskills.io)：每个技能一个文件夹，各含一个 `SKILL.md`，发布在 [{{value:skillsRepo}}]({{value:repoUrl}})。本页的每条命令安装的都是版本 [`{{value:releaseTag}}`]({{value:releaseUrl}})。

## 开始之前 {#before}

这些技能通过 Motir 的 MCP 服务器与 Motir 通信。在 Claude Code 中，插件会替你连接它：你在浏览器中用 Motir 账户登录，不需要令牌。其他所有智能体都需要先连接这个服务器——需要一个 Motir 项目、一个个人访问令牌，以及 [{{value:mcpPage}}](/docs/mcp) 指南中针对你的智能体的设置；如果无法使用浏览器登录，该指南也介绍了 Claude Code 中的令牌路线。使用默认权限的令牌，就可以完成这些技能所做的一切。你还需要 `git`，以及用于打开或读取拉取请求的技能所需的 GitHub CLI（`gh`）。

## 使用 {#use}

把 **你可以说** 下面的内容输入到你的智能体中。把 `ACME-12` 换成你自己项目中某个工作项的键。

### `motir-run` {#motir-run}

**你可以说**

- `motir run`
- `motir run ACME-12`
- `motir next`

**会发生什么**

领取你项目中下一个就绪的工作项，或你指定的那个，并构建它。它先收尾此前那些拉取请求已经合并的运行，然后领取该工作项，在属于它自己的分支上构建，打开一个拉取请求，并把该拉取请求关联到工作项。若指定的是一个故事，且其子项都没有自己的子项，它会运行整个故事：每个仓库一个分支、一个拉取请求，每个子项一次提交。`motir next` 在领取之后就会停下并打印提示词，由你自己交给某个智能体。决策工作项是唯一的例外：它会撰写决策页面并发布，等待你批准，不产生分支，也不产生拉取请求。

**你在 Motir 中看到什么**

该工作项会被分配给你并变为进行中，拉取请求打开后变为已实现。它的页面会显示拉取请求和“如何测试”部分。CI 通过时由 Motir 把它移到评审中，拉取请求合并时移到已完成；技能自己从不做这两件事。

### `motir-fix` {#motir-fix}

**你可以说**

- `motir fix ACME-12`

**会发生什么**

在打开拉取请求的那次运行结束之后，修复一个红色的拉取请求：它的检查失败了、合并队列把它踢了出来，或者评审者把故事的验收视频以“重新运行”退了回来。它首先领取这次修复，这样别人就不会在它之上推送。然后它在工作项每个拉取请求已有的分支上修复，绝不新建分支：合并基础分支，修复失败的检查所指出的故障，然后推送。它会一直进行到 CI 变绿，或已尝试五次；在“重新运行”之后 CI 变绿时，它会重新录制验收视频。它绝不会打开拉取请求、合并拉取请求，也不会更改工作项的状态。它不同于 `motir fix bugs`，后者处理你项目的缺陷文件夹：`motir fix ACME-12` 修复的是你指定的那一个工作项的拉取请求。

**你在 Motir 中看到什么**

修复进行期间，工作项的“开发”部分会说明它正在被修复，以及由谁修复。相同的拉取请求会得到新的提交，一旦它们的检查通过，Motir 会自动推进该工作项。如果修复放弃了，工作项会说明这一点，以及尝试了多少次。

### `motir-continue` {#motir-continue}

**你可以说**

- `motir continue ACME-12`

**会发生什么**

接续一个运行中途中断的工作项：笔记本合上了、沙箱丢失了，或进程被终止了。该工作项仍处于进行中，它的工作留在那次运行遗留的分支上。它首先领取这次接续，这样别人就不会在同一个分支上工作。然后它在工作项涉及的每个仓库中检出那个分支，绝不新建分支，也绝不重置已有的内容，并从中断的地方继续工作。它的交付方式与全新的运行相同：每个仓库一个拉取请求，关联到该工作项。如果工作项已经有一个红色的拉取请求，请改用 `motir fix ACME-12`；对于还没有人开始的工作项，用 `motir run ACME-12`。

**你在 Motir 中看到什么**

运行中断的工作项会在它的“开发”部分显示“运行已中断”，并附上可复制的 `motir continue` 命令。接续进行期间，该部分会说明它正在被接续，以及由谁接续。完成后，工作项的推进方式与 `motir run` 之后完全相同：变为已实现，拉取请求已关联，并带有“如何测试”部分。

### `motir-log-bug` {#motir-log-bug}

**你可以说**

- `motir log bug the export button does nothing on an empty board`

**会发生什么**

把你输入的内容当作需要核实的论断。它先在代码中找出原因，查找别人是否已经提交过相应的工作项，如果发现该行为其实是正确的，就什么都不提交。否则它会提交一个缺陷：放在它所阻塞的故事之下；如果它不阻塞任何东西，则放在项目的缺陷文件夹中。

**你在 Motir 中看到什么**

一个新的缺陷工作项，包含原因、它在代码中的位置以及复现方式，并关联到发现它的那个工作项。如果它阻塞了你正在运行的工作项，那个工作项会变为受阻。

### `motir-mark` {#motir-mark}

**你可以说**

- `motir mark ACME-12 done`

**会发生什么**

关闭一个任何拉取请求都无法关闭的工作项：手动的那种，例如创建账户、设置密钥或更改某项设置。你说出这句话，就是在确认工作已经完成。如果工作项带有拉取请求，它会拒绝，因为是该拉取请求的合并来关闭它。

**你在 Motir 中看到什么**

工作项变为已完成，并附一条评论，记录是你确认的。其父项的状态会随其子项而定。

### `motir-guide` {#motir-guide}

**你可以说**

- `motir guide ACME-12`
- `motir guide`

**会发生什么**

一步一步带你完成一个手动工作项。指定一个，或者只说 `motir guide`，它就会接手你自己尚未完成的那个，否则接手下一个就绪的手动工作项。它给你一个步骤，附带该步骤的说明和任何要复制的命令，然后等待。你说“完成”，它就会检查它在不做任何更改的前提下能检查的内容，例如访问某个地址或运行只读命令，并告诉你它看到了什么。检查失败的步骤不会被勾选；你会再次得到同一个步骤。你可以在任何一步停下，`motir guide` 会从你停下的地方继续。如果工作项还没有步骤，它会根据描述提出一些步骤，并在把它们写入工作项之前征求你的意见。如果某个步骤被发现有误，它会提出更正，只有在你同意时才会更改该步骤或工作项的文字。

**你在 Motir 中看到什么**

工作项被分配给你并变为进行中。它的待办清单会在你完成每一步时勾选该步骤，并记录是谁完成的。最后一步被勾选后，工作项变为已完成，并附一条评论，概述每一步以及是如何确认的。

### `motir-fix-bugs` {#motir-fix-bugs}

**你可以说**

- `motir fix bugs`
- `motir fix bugs 3`

**会发生什么**

逐个处理你项目缺陷文件夹中仍处于待办的缺陷，一次一个，最旧的优先。缺陷文件夹内的子文件夹中的缺陷不处理。对每一个，它先确认该缺陷在你的默认分支上确实存在，然后给它恰好一种结果。能修复的缺陷会得到一个只修复该缺陷、不含其他内容的拉取请求。依赖于另一个尚未完成的工作项的缺陷，会关联到那个工作项，并移到同一个故事之下。无法在这里修复的缺陷会得到一条评论并被搁置：已经修复，并说明是什么修复了它；无法复现，并说明它运行了什么；或需要你来决定，并附上需要你回答的提问和它的建议。每种结果都会让该缺陷离开待办，所以运行会自行结束。加上一个数字，处理完那么多个缺陷后它就会停止。它以一份报告收尾，其中先列出在等你的缺陷。

**你在 Motir 中看到什么**

修复好的缺陷变为已实现，并关联其拉取请求，你合并后变为已完成。在等待其他工作的缺陷变为受阻，并带有指向那个工作项的“被阻塞”链接。已经修复的缺陷变为已完成。无法复现的缺陷，或需要你决定的缺陷，变为受阻。这些都附有一条写明证据或提问的评论。回答该提问并把缺陷移回待办，下一次运行就会接手它。

## 当工作项有误时 {#wrong}

有时一个工作项无法按所写的内容构建。它可能要求某个不存在的东西，需要一份没有人画过的设计，或者涉及两个仓库。`motir-run` 不会猜着绕过去。它会把工作项移到 **规划中**，这样其他运行就不会接手它，并请 Motir AI 规划器规划更正。然后停下。该计划等待你在 Motir 中评审并批准，在你批准之前不会构建任何东西。

如果你的令牌无法使用 AI 规划，或者你的 AI 额度用完了，它仍然会停下。它会在工作项上留下一条包含完整更正的评论，并说明为什么无法移交。
