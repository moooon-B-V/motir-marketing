Motir의 스킬을 쓰면 이미 사용 중인 에이전트가 Motir 프로젝트에서 일할 수 있습니다. `motir run`이라고 말하면 준비된 다음 작업 항목을 가져와 구현하고, 연결된 풀 리퀘스트를 엽니다. `motir log bug`라고 말하면 결함을 확인한 뒤 알맞은 위치에 등록합니다. `motir mark`라고 말하면 사용자가 직접 끝낸 수동 작업 항목을 닫습니다. `motir guide`라고 말하면 수동 작업 항목을 한 번에 한 단계씩 안내합니다.

이 스킬들은 평범한 [Agent Skills](https://agentskills.io)입니다. 스킬마다 폴더가 하나씩 있고 각각 `SKILL.md`가 있으며, [{{value:skillsRepo}}]({{value:repoUrl}})에 게시되어 있습니다. 이 페이지의 모든 명령은 릴리스 [`{{value:releaseTag}}`]({{value:releaseUrl}})를 설치합니다.

## 시작하기 전에 {#before}

스킬은 MCP 서버를 통해 Motir와 통신합니다. Claude Code에서는 플러그인이 서버를 연결해 줍니다. 브라우저에서 Motir 계정으로 로그인하면 되고 토큰은 필요 없습니다. 그 밖의 에이전트는 먼저 해당 서버를 연결해야 합니다. Motir 프로젝트, 개인 액세스 토큰, 그리고 [{{value:mcpPage}}](/docs/mcp) 가이드에 있는 에이전트별 설정이 필요하며, 이 가이드에는 브라우저 로그인을 쓸 수 없을 때 Claude Code에서 토큰을 쓰는 방법도 나와 있습니다. 기본 권한의 토큰이면 이 스킬들이 하는 모든 일을 할 수 있습니다. `git`도 필요하고, 풀 리퀘스트를 열거나 읽는 스킬에는 GitHub CLI(`gh`)도 필요합니다.

## 설치 {#install}

사용하는 에이전트를 고르세요. 각 섹션은 릴리스의 모든 스킬을 컴퓨터의 모든 프로젝트용으로 설치합니다. 터미널 명령은 macOS와 Linux용입니다. 릴리스를 내려받고, 스킬 폴더를 해당 에이전트가 읽는 폴더에 복사한 다음, 다운로드한 파일을 삭제합니다.

## 사용하기 {#use}

**말하기** 아래의 내용을 에이전트에 입력하세요. `ACME-12`는 자신의 프로젝트에 있는 작업 항목의 키로 바꾸세요.

### `motir-run` {#motir-run}

**말하기**

- `motir run`
- `motir run ACME-12`
- `motir next`

**동작**

프로젝트에서 준비된 다음 작업 항목, 또는 지정한 작업 항목을 가져와 구현합니다. 먼저 풀 리퀘스트가 병합된 이전 실행의 뒷정리를 하고, 작업 항목을 가져온 다음, 전용 브랜치에서 구현하고, 풀 리퀘스트를 하나 열어 작업 항목에 연결합니다. 하위 항목에 다시 하위 항목이 없는 스토리를 지정하면 스토리 전체를 실행합니다. 저장소마다 브랜치 하나와 풀 리퀘스트 하나를 만들고, 하위 항목마다 커밋을 하나씩 남깁니다. `motir next`는 작업 항목을 가져온 뒤 멈추고 프롬프트를 출력하므로, 이를 직접 에이전트에 넘길 수 있습니다. 결정 작업 항목은 예외입니다. 브랜치도 풀 리퀘스트도 없이 결정 페이지를 작성해 사용자의 승인을 받도록 게시합니다.

**Motir에서 보이는 것**

작업 항목이 사용자에게 지정되고 진행 중으로 이동하며, 풀 리퀘스트가 열리면 구현됨으로 이동합니다. 작업 항목 페이지에 풀 리퀘스트와 테스트 방법 섹션이 표시됩니다. Motir는 CI가 통과하면 검토 중으로, 풀 리퀘스트가 병합되면 완료로 이동시키며, 스킬은 둘 다 직접 하지 않습니다.

### `motir-fix` {#motir-fix}

**말하기**

- `motir fix ACME-12`

**동작**

풀 리퀘스트를 연 실행이 끝난 뒤에 실패한 풀 리퀘스트를 복구합니다. 검사가 실패했거나, 병합 큐가 걸러 냈거나, 검토자가 스토리의 인수 영상을 다시 실행으로 돌려보낸 경우입니다. 먼저 복구를 가져와서 아무도 그 위에 푸시하지 못하게 합니다. 그런 다음 작업 항목의 각 풀 리퀘스트를 이미 있는 브랜치에서 고치며, 새 브랜치는 만들지 않습니다. 기준 브랜치를 병합하고, 실패한 검사가 지목한 문제를 고친 다음 푸시합니다. CI가 통과하거나 다섯 번 시도할 때까지 계속하며, 다시 실행 이후 CI가 통과하면 인수 영상을 다시 녹화합니다. 풀 리퀘스트를 열거나, 병합하거나, 작업 항목의 상태를 바꾸는 일은 절대 하지 않습니다. 프로젝트의 버그 폴더를 처리하는 `motir fix bugs`와는 다릅니다. `motir fix ACME-12`는 지정한 작업 항목 하나의 풀 리퀘스트를 복구합니다.

**Motir에서 보이는 것**

복구가 진행되는 동안 작업 항목의 개발 섹션에 수정 중이라는 것과 수정하는 주체가 표시됩니다. 같은 풀 리퀘스트에 새 커밋이 추가되고, 검사가 통과하면 Motir가 작업 항목을 스스로 다음 상태로 옮깁니다. 복구를 포기하면 작업 항목에 그 사실과 시도한 횟수가 표시됩니다.

### `motir-continue` {#motir-continue}

**말하기**

- `motir continue ACME-12`

**동작**

실행이 도중에 중단된 작업 항목을 이어서 진행합니다. 노트북이 닫혔거나, 샌드박스가 사라졌거나, 프로세스가 종료된 경우입니다. 작업 항목은 여전히 진행 중이며 작업 내용은 그 실행이 남긴 브랜치에 있습니다. 먼저 이어하기를 가져와서 아무도 같은 브랜치에서 작업하지 못하게 합니다. 그런 다음 작업 항목에 걸친 모든 저장소에서 그 브랜치를 체크아웃합니다. 새 브랜치는 만들지 않고, 이미 있는 내용도 초기화하지 않으며, 멈춘 지점에서 작업을 이어갑니다. 새 실행과 똑같이 전달합니다. 저장소마다 풀 리퀘스트를 하나씩 만들어 작업 항목에 연결합니다. 작업 항목에 이미 실패한 풀 리퀘스트가 있다면 대신 `motir fix ACME-12`를, 아무도 시작하지 않은 작업 항목에는 `motir run ACME-12`를 사용하세요.

**Motir에서 보이는 것**

실행이 중단된 작업 항목은 개발 섹션에 실행 중단됨이라고 표시되며, 복사해 쓸 수 있는 `motir continue` 명령이 함께 나옵니다. 이어하기가 진행되는 동안 그 섹션에 이어서 진행 중이라는 것과 진행하는 주체가 표시됩니다. 끝나면 작업 항목은 `motir run` 이후와 똑같이 구현됨으로 이동하며, 풀 리퀘스트가 연결되고 테스트 방법 섹션이 생깁니다.

### `motir-log-bug` {#motir-log-bug}

**말하기**

- `motir log bug the export button does nothing on an empty board`

**동작**

입력한 내용을 확인해야 할 주장으로 취급합니다. 먼저 코드에서 원인을 찾고, 이미 누군가 등록한 작업 항목이 있는지 찾아보며, 알고 보니 그 동작이 올바른 것이라면 아무것도 등록하지 않습니다. 그렇지 않으면 버그 하나를 등록합니다. 그 버그가 막고 있는 스토리 아래에 등록하고, 아무것도 막지 않으면 프로젝트의 버그 폴더에 등록합니다.

**Motir에서 보이는 것**

원인, 코드에서의 위치, 재현 방법이 담긴 새 버그 작업 항목이 만들어지며, 이 버그가 발견된 작업 항목에 연결됩니다. 지금 실행 중인 작업 항목을 막는다면 그 작업 항목은 차단됨으로 이동합니다.

### `motir-mark` {#motir-mark}

**말하기**

- `motir mark ACME-12 done`

**동작**

어떤 풀 리퀘스트로도 닫을 수 없는 작업 항목을 닫습니다. 계정 만들기, 시크릿 설정, 설정 변경 같은 수동 작업이 그 예입니다. 이렇게 말하는 것이 작업이 끝났다는 사용자의 확인입니다. 풀 리퀘스트가 있는 작업 항목은 그 풀 리퀘스트의 병합이 닫으므로 거절합니다.

**Motir에서 보이는 것**

작업 항목이 완료로 이동하며, 사용자가 확인했다는 사실을 기록한 댓글이 남습니다. 상위 항목의 상태는 하위 항목들로부터 결정됩니다.

### `motir-guide` {#motir-guide}

**말하기**

- `motir guide ACME-12`
- `motir guide`

**동작**

수동 작업 항목을 한 번에 한 단계씩 안내합니다. 작업 항목을 지정하거나 `motir guide`만 말하면, 사용자 본인의 끝나지 않은 작업 항목을 이어서 맡고, 없으면 준비된 다음 수동 작업 항목을 맡습니다. 지침과 복사할 명령이 담긴 단계 하나를 보여 주고 기다립니다. 완료했다고 말하면 주소를 가져오거나 읽기 전용 명령을 실행하는 등 아무것도 바꾸지 않고 확인할 수 있는 것을 확인한 뒤 본 내용을 알려 줍니다. 확인에 실패한 단계는 완료로 표시되지 않으며, 같은 단계가 다시 나옵니다. 어느 단계에서든 멈출 수 있고, `motir guide`는 멈춘 곳에서 다시 시작합니다. 작업 항목에 아직 단계가 없다면 설명을 바탕으로 몇 가지를 제안하고, 작업 항목에 기록하기 전에 사용자에게 먼저 묻습니다. 단계가 잘못된 것으로 드러나면 수정안을 제시하고, 사용자가 승인할 때만 단계나 작업 항목의 텍스트를 바꿉니다.

**Motir에서 보이는 것**

작업 항목이 사용자에게 지정되고 진행 중으로 이동합니다. 할 일 목록에서 각 단계를 마칠 때마다 누가 했는지와 함께 체크됩니다. 마지막 단계가 체크되면 작업 항목이 완료로 이동하며, 각 단계와 확인 방법을 요약한 댓글이 남습니다.

### `motir-fix-bugs` {#motir-fix-bugs}

**말하기**

- `motir fix bugs`
- `motir fix bugs 3`

**동작**

프로젝트의 버그 폴더에서 아직 할 일 상태인 버그를 오래된 순서대로 한 번에 하나씩 처리합니다. 버그 폴더 안에 있는 하위 폴더의 버그는 건드리지 않습니다. 각 버그에 대해 먼저 기본 브랜치에서 실제로 발생하는 버그인지 확인한 뒤, 정확히 하나의 결과를 줍니다. 고칠 수 있는 버그는 그 버그만 고치는 풀 리퀘스트 하나를 받습니다. 아직 끝나지 않은 다른 작업 항목을 기다리는 버그는 그 작업 항목에 연결되고 같은 스토리 아래로 옮겨집니다. 여기서 고칠 수 없는 버그는 댓글을 받고 한쪽으로 치워집니다. 이미 고쳐졌다면 무엇이 고쳤는지, 재현할 수 없다면 무엇을 실행해 봤는지, 사용자의 결정이 필요하다면 질문과 추천안을 적습니다. 모든 결과는 버그를 할 일에서 빼내므로 실행은 스스로 끝납니다. 숫자를 덧붙이면 그만큼의 버그를 처리한 뒤 멈춥니다. 사용자를 기다리는 버그를 맨 앞에 나열한 보고서로 끝납니다.

**Motir에서 보이는 것**

고친 버그는 풀 리퀘스트가 연결된 채 구현됨으로 이동하고, 병합하면 완료로 이동합니다. 다른 작업을 기다리는 버그는 그 작업 항목에 대한 차단하는 항목 링크와 함께 차단됨으로 이동합니다. 이미 고쳐진 버그는 완료로 이동합니다. 재현할 수 없거나 사용자의 결정이 필요한 버그는 차단됨으로 이동합니다. 이들 모두에 증거나 질문이 담긴 댓글이 남습니다. 질문에 답하고 버그를 다시 할 일로 옮기면 다음 실행이 그것을 처리합니다.

## 작업 항목이 잘못된 경우 {#wrong}

작업 항목을 적힌 대로 구현할 수 없는 경우가 있습니다. 존재하지 않는 것을 요구하거나, 아무도 그리지 않은 디자인이 필요하거나, 두 저장소에 걸쳐 있을 수 있습니다. `motir-run`은 이를 요령껏 우회하려 하지 않습니다. 다른 실행이 가져가지 못하도록 작업 항목을 **계획 중**으로 옮기고, Motir의 AI 플래너에게 수정안을 계획하도록 요청한 뒤 멈춥니다. 계획은 사용자가 Motir에서 검토하고 승인하기를 기다리며, 승인할 때까지 아무것도 구현되지 않습니다.

토큰으로 AI 계획을 사용할 수 없거나 AI 크레딧이 소진되었다면 그래도 멈춥니다. 작업 항목에 수정안 전체와 넘길 수 없었던 이유를 댓글로 남깁니다.
