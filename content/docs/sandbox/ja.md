サンドボックスは、お使いのマシン上で起動するコンテナーで、あなた自身のエージェント、Motir CLI、チェックアウトしたリポジトリだけが入っています。エージェントの認証情報は、読み取り専用でマウントして持ち込みます。ループはコンテナーの内側で動くので、エージェントが誤動作しても、影響が及ぶのは作業ツリーまでで、マシンのそれ以外の部分には及びません。

## 始める前に {#before-you-start}

- **Docker が起動していること。** `linux/amd64` と `linux/arm64` **の両方**向けにビルドされているため、Apple Silicon でもそのまま動作し、エミュレーションは行われません。ビルドの手順はありません。イメージをプルするだけです。
- **このマシンに、お使いのエージェント自身のサインインがあること。** 認証情報のマウントは読み取り専用なので、コンテナーはサインインを利用できますが、更新はできません。macOS の Claude Code は例外で、トークンをログインキーチェーンに保存するため、マウントできるファイルがありません。その場合は、コンテナーの**内側**で `claude` にサインインします。イメージには書き込み可能な設定ディレクトリが用意されていて、サインインはそこに保存されます。（Antigravity も同様です。選択したときに手順 2 で説明します。）
- **ワークスペースのルート — チェックアウトしたリポジトリを含むフォルダー。** 1 つのプロジェクトは通常、複数のリポジトリにまたがり、ループはそのすべてを横断して動作します。

{{part:step-1-intent}}

エージェント用のイメージをプルする

{{part:step-1-body}}

ビルドの手順はありません。イメージはエージェントのプロファイルごとに公開されています。

{{part:step-2-intent}}

ワークスペースのルートからコンテナーを起動する

{{part:step-2-body}}

チェックアウトしたリポジトリのどれか 1 つの中ではなく、それらを**含む**フォルダーから実行してください。

{{part:step-2-vscode}}

**代わりに VS Code を使う場合は、** 以下の手順 2a〜2c が、この手順に置き換わります。その後の手順は、どちらの方法でも同じです。

{{part:step-2a-intent}}

Dev Containers 拡張機能をインストールする

{{part:step-2a-body}}

拡張機能ビューから、またはコマンドパレットからインストールします。コマンドパレットは、macOS では ⇧⌘P、それ以外では Ctrl+Shift+P、どの環境でも F1 で開き、_Extensions: Install Extensions_ を選びます。この 3 つの手順のうち 2 つはコマンドパレットで行うので、今のうちにピン留めしておくと便利です。

{{part:step-2b-intent}}

開発コンテナーの設定を作成する

{{part:step-2b-body}}

マウントするフォルダーの中で、これを実行してください。1 回の貼り付けで、`.devcontainer` フォルダーが作られ、その中にファイルが書き込まれます。ファイル選択ダイアログからこれらを作ろうとしないでください。Finder や多くの GUI のダイアログは、ドットで始まる名前を拒否し、しかも理由を示しません。

{{part:step-2b-warning}}

**開発コンテナーは、作成時のイメージをそのまま保持します。** `--pull=always` は手順 2 の実行コマンドのものであり、この方法には含まれません。現在のイメージと `motir` CLI に更新するには、次の順に行います。**1.** お使いのマシンのターミナルで、手順 1 の `{{value:dockerPull}}` を実行します。**2.** このフォルダーで _Dev Containers: Open Folder in Container…_ を実行し、ウィンドウをコンテナーにアタッチします。**3.** _Dev Containers: Rebuild Container_ を実行し、プルしたばかりのイメージからコンテナーを作り直します。_Rebuild Container_ は、コンテナーにアタッチしたウィンドウにしか表示されないため、手順 2 が先になります。再構築しても Motir のサインイン（`{{value:authVolume}}` ボリュームにあります）は保持されますが、コンテナー内で行った Claude Code のサインインは保持されません。`claude` を実行して、もう一度サインインしてください。

{{part:step-2c-intent}}

コンテナーでフォルダーを開く

{{part:step-2c-body}}

コマンドパレットで _Dev Containers: Open Folder in Container…_ を実行し、ファイルを書き込んだばかりのフォルダーを選びます。そのターミナルは、手順 2 で入るはずだったシェルと同じものです。手順 3 に進んでください。

{{part:step-3-intent}}

コンテナーの内側でサインインする

{{part:step-3-body}}

コードと URL が表示されるので、任意のブラウザーで承認します。サインインは `{{value:authVolume}}` ボリュームに保存されるため、行うのは一度だけです。

{{part:step-4-intent}}

フォルダーをプロジェクトにリンクする

{{part:step-4-body}}

`ACME` を、ご自身のプロジェクトキーに置き換えてください。ワークスペースにプロジェクトが 1 つだけなら、フラグは不要です。それがこの手順のすべてです。

{{part:step-5-intent}}

確認する — すべて緑になれば、このページはここで終わりです

{{part:step-5-body}}

認証、リンク、エージェントのバイナリ、その認証情報を確認します。渡したものをコンテナーが実際に受け取ったかどうかがわかるのは、この確認だけです。

{{part:note-opencode}}

OpenCode は設定と認証情報を 2 か所に保存するため、`-v` の行が 2 つ必要です。どちらも必要です。

{{part:note-antigravity}}

Antigravity はトークンを OS のキーリングに保存しており、バインドできる移植可能なファイルがありません。そのため `-v` の行はなく、起動前ではなくコンテナーの内側でサインインします。これは、上の 2 つ目の前提条件が当てはまらない唯一のプロファイルです。

{{part:note-aider}}

Aider の認証情報は、環境変数から読み取るモデルの API キーです。そのため、`-e` の行が加わる唯一のプロファイルです。バインドするのはファイルで、空でも構わないので存在している必要があります。存在しないと、Docker が代わりにディレクトリを作成してしまいます。

{{part:note-base}}

ベースイメージには Motir CLI だけが入っており、エージェントは入っていません。マウントするものも、Motir 以外にサインインするものもありません。

{{part:devcontainer-file}}

### このコマンドが書き込むファイル {#devcontainer-file}

これは手順ではなく参考情報です。ファイルは 2b ですでに書き込まれています。ファイルを自分で作りたい方のために、そして `<<’JSON’` を囲む引用符が重要であるため、ここに載せています。この引用符によって、`${localWorkspaceFolder}` と `${localEnv:HOME}` がファイルに届く前にシェルに展開されることを防いでいます。これらは Dev Containers の置換であり、解決するのはエディターです。

## このような構成になっている理由 {#why}

### プロファイルの選択で変わるもの {#profile-picker}

エージェントを選ぶと、イメージの**タグ**、認証情報の `-v` の行、開発コンテナーの `image`、`name`、`mounts` の 3 つだけが書き換わります。置き換えるよう文章で指示するのではなく、操作できるコントロールにしているのは、ここにあるコマンドにはすべてコピーボタンがあり、コピーする人は置き換えの指示を読まないからです。

すべてのプロファイルが認証情報のディレクトリを 1 つだけ持つわけではありません。`opencode` は 2 つ持つため `-v` の行が 2 つ必要です。`antigravity` はトークンを OS のキーリングに保存するためバインドの行はなく、代わりにコンテナー内でサインインします。`aider` はファイルをバインドし、モデルのキーを環境変数から読み取ります。選択したときに、手順の中でそのことを説明します。

### 実行コマンドでは、古くなりうるものは何も残らない {#run-command}

`--pull=always` は起動のたびに最新のイメージを取得します。プロファイルのタグが動いても、その変更に気づかないまま最新のものが届き、`--rm` により、古くなりうるものは何も残りません。「戻ってきたとき」のための別の経路はありません。以前は、読んでいるページより数か月古い `motir` を使っている人がいましたが、その原因がまさにそれでした。サインインはこうした変更の影響を受けません。コンテナーの外にある `{{value:authVolume}}` ボリュームに書き込まれるため、サインインは一度だけで、以降の実行では自動的に引き継がれます。完全にサインアウトするには `{{value:signOutCommand}}` を実行します。オフラインで作業する場合は `--pull=always` を外してください。このオプションは起動のたびにレジストリにアクセスするため、ネットワークがないと、すでにあるイメージにフォールバックせず、実行が失敗します。ここまでの内容は、すべて実行コマンドについてのものです。開発コンテナー（手順 2a〜2c）は、プルするまで作成時のイメージを保持します。更新するには、_Dev Containers: Open Folder in Container…_ でアタッチし、_Dev Containers: Rebuild Container_ を選んでください。

### 次のステップ {#what-next}

`motir run` は、1 つの作業項目、ストーリー全体、またはアクティブな Sprint を表す `sprint` という範囲を受け取ります。`motir auto` は代わりに、実行可能な項目を無人で順に処理し、1 つずつセッションブランチに積んでいきます。どちらも受け付けるすべてのフラグは、[{{value:cliPage}}](/docs/cli)のページにあります。

## 何を閉じ込め、何を閉じ込めないか {#confines}

信頼を預ける前にお読みください。次の 3 つのうち 1 つは、保証ではなく例外だからです。

- **ファイルシステム — 閉じ込められる。** コンテナー内に見えるホスト側のものは、書き込み可能な `/workspace` と、読み取り専用でマウントされたエージェント自身の認証情報だけです。Docker ソケットも、それ以外のホストのバインドもありません。
- **ネットワーク — 設計上、開放されている。** どのエージェントもプロバイダーの API を必要とし、ディスパッチされるどの作業項目も git のリモートを必要とします。そのためイメージが制限するのはファイルシステム上の影響範囲であり、外向きの通信ではありません。脅威モデルがそれ以上を要求する場合は、Docker 自体のネットワーク制御を使ってください。コンテナーは、エージェントがインターネットと通信するのを止めません。
- **権限 — 非特権。** `node` ユーザー（ユーザー ID 1000）として動作するため、マウント先に書き込まれたファイルの所有者は root ユーザーではなく、あなたのままです。

## 環境が提供するもの {#environment}

- **マウントされたあなたのフォルダー。** `$PWD` が `/workspace` になるため、実行が作業するチェックアウトはあなた自身のものであり、実行が行ったコミットは、終了後もあなたのディスクに残ります。
- **作業項目ごとに 1 つのチェックアウト（git ワークツリー）。** 実行は、あなたが今開いているツリーを編集しません。項目ごとにワークツリーを追加するので、並行する実行同士がブランチのチェックアウトで衝突することはありません。
- **あなたのエージェントの認証情報（読み取り専用）。** プロファイルの認証情報ディレクトリは、`:ro` でバインドマウントされます。コンテナー内の何もそれを書き換えられず、それに関する情報が Motir に送られることもありません。これは自前のキーを持ち込む方式なので、エージェントの利用料金はお客様の負担となり、API 呼び出しが Motir を経由することはありません。
- **CLI はインストール済み。** イメージには `motir` と、タグが指すエージェントのバイナリが入っているため、最初の実行の前にインストールするものはありません。
- **エージェントの出力は、デフォルトではローカルに残ります。** Motir に届くのは、実行のライフサイクルだけです。`--report-log` を付けると、出力の末尾も追加で送信され、失敗した実行の出力を実行ページで確認できます。指定しない限りオフで、どちらの場合でも、ファイルの内容、パス、差分が送信されることはありません。

## トークンができること、拒否されること {#token}

`motir login` が発行するトークンには、狭められた固定の権限が付与されます。承認画面にはその内容が表示されますが、変更はできません。広げることも狭めることもできません。手作業で狭めた権限では、無人のループが途中で止まってしまうからです。

{{slot:grant}}

**付与されない権限は `ai:view_plan` で、その結果として拒否されるのはバグではなく設計どおりです。** 計画を開くのに必要なのは `work_item:edit` だけなので、サンドボックス内の実行は計画を開くことはできます。ただし、最初の追記で拒否されます。提案を追加する操作が主張するのはその権限だからです。作業項目を実行している実行が、渡された計画を作り替えることは許されていません。この拒否に遭遇したなら、エージェントは正しく動作したということです。エージェントは修正をコメントとして記録し、その項目をブロック中のままにして、停止します。何も失われず、計画に何を書くかは人が決めます。

より静かな実行にしたい場合は、2 つのフラグでさらに絞り込めます。`--disable-log-bug` は、エージェントが別の場所で見つけた不具合についてバグを登録するのを止めます（代わりにコメントします）。`--disable-replan` は、誤りがあると判断した作業項目について再計画を提出するのを止めます（コメントして停止します）。`motir auto` に限り、`--auto-approve-replan` は逆の動作をします。提出された再計画を承認してループを続け、あなたのために停止することはありません。

## 実行が生み出すもの、確認できる場所 {#produces}

- **ブランチとプルリクエスト。** 項目を届けるリポジトリごとに作られ、コンテナーの内側から、あなたの git 認証情報でプッシュされます。
- **作業項目のリンク。** 実行は、各プルリクエストがどの項目を届けるのかを宣言するため、そのプルリクエストをマージすると、作業項目が動きます。項目ページの「開発」パネルに表示されるのがこのリンクで、マージ時に項目をクローズするのもこのリンクです。ブランチ名やタイトルではありません。
- **進行に応じたステータス。** 項目は、実行が確保した時点で進行中に、プルリクエストが開かれた時点で実装済みになります。レビュー中は、チェックが緑になったときに CI が、完了はマージが書き込みます。
- **ターミナル。** エージェント自身の出力は、`--report-log` を付けない限り、あなたのターミナルに留まります。

## うまく動作しないとき {#troubleshooting}

### エージェントのバイナリが見つからない {#agent-binary-not-found}

タグとエージェントが一致していません。どのプロファイルを起動したかを確認するか、`--agent <cmd>` で実行に別のバイナリを指定してください。`motir doctor` は、実行が確保を無駄にする前に、この問題を報告します。

### エージェントは起動するが、認証されていない {#agent-not-authenticated}

認証情報のマウントがないか、誤ったディレクトリを指しています。プロファイルごとに、それぞれのディレクトリをマウントします。実際にプルしたタグ向けの `{{value:dockerRun}}` の行を、もう一度実行してください。

### 実行できるものがない {#nothing-ready}

候補のすべてに、未解決の依存関係があります。`motir ready` で一覧を確認でき、作業項目に対する `motir show` で、何がブロックしているかがわかります。それでもディスパッチするには `--force` を使います。対象は 1 つの項目だけです。

### 提出された再計画で実行が停止する {#stopped-on-replan}

エージェントが作業項目に誤りがあると判断し、修正した形を提案しました。これは意図した停止です。Motir で計画を読み、承認または却下してください。無人のループを止めずに続けたい場合は、`motir auto` を `--auto-approve-replan` 付きで実行します。

### 実行が終了した後に作業が残った {#work-left-behind}

ワークツリーとブランチは、マウントしたフォルダーの下のあなたのディスクにあります。停止したコンテナーがそれらを持ち去ることはありません。`motir done` は、マージされた項目を、または `--session <branch>` を付けて、マージされたセッションブランチ全体を、クローズします。
