沙箱是在你自己的机器上启动的容器，里面只有你自己的智能体、Motir CLI 和你的仓库副本——别无他物。你自带智能体凭据，并以只读方式挂载；循环在容器内运行，因此行为失当的智能体只能触及你的工作树，而无法触及机器上的其他部分。

## 开始之前 {#before-you-start}

- **Docker，已在运行。** 同时构建了 `linux/amd64` **和** `linux/arm64` 两种版本，因此 Apple Silicon 是一等公民，没有任何模拟。没有构建步骤——直接拉取。
- **你的智能体自己的登录状态，就在这台机器上。** 它的凭据挂载是只读的，所以容器可以使用某个登录状态，却不能续期。你会遇到的例外是 macOS 上的 Claude Code：它把令牌保存在登录钥匙串中，因此没有可挂载的文件，需要改为在容器 **内部** 登录 `claude`——镜像为它提供了可写的配置目录，登录状态就落在那里。（Antigravity 同理——你选择它时，第 2 步会说明。）
- **你的工作区根目录——包含各个仓库副本的那个文件夹。** 一个项目通常横跨多个仓库，循环会在所有这些仓库中运行。

{{part:step-2b-intent}}

创建开发容器配置

{{part:step-2b-body}}

在你要挂载的文件夹中运行。一次粘贴即可：它会创建 `.devcontainer` 文件夹，并把文件写入其中。不要尝试通过文件选择器创建它们——Finder 和大多数图形界面的选择器都不接受以点开头的名称，而且拒绝时不会告诉你原因。

{{part:step-2b-warning}}

**开发容器会保留创建它时所用的镜像。** `--pull=always` 属于第 2 步的运行命令，不属于这条路线。要切换到当前的镜像和 `motir` CLI：**1.** 在你机器上的终端里运行第 1 步的 `{{value:dockerPull}}`；**2.** 对此文件夹执行 _Dev Containers: Open Folder in Container…_，这会附加窗口；**3.** 执行 _Dev Containers: Rebuild Container_，它会用你刚拉取的镜像重新创建容器。“Rebuild Container”只会出现在已附加到容器的窗口中，所以必须先做第 2 步。重新构建会保留你的 Motir 登录状态（它存放在 `{{value:authVolume}}` 卷上），但不会保留在容器内完成的 Claude Code 登录——请运行 `claude` 并重新登录。

{{part:note-opencode}}

OpenCode 把配置和凭据保存在两个位置，所以需要两条 `-v` 行。两条都必须有。

{{part:note-antigravity}}

{{part:note-base}}

基础镜像只带有 Motir CLI，完全没有智能体——没有需要挂载的东西，除了 Motir 本身也没有需要登录的东西。

## 为什么是这样 {#why}

### 配置文件选择器改变了什么 {#profile-picker}

选择一个智能体会改写三样东西，仅此而已：镜像 **标签**、凭据的 `-v` 行，以及开发容器的 `image`、`name` 和 `mounts`。之所以做成一个控件，而不是一段让你自己去替换的文字，是因为这里的每条命令都有“复制”按钮，而会去复制的读者，就是不会去读替换说明的读者。

并非每个配置文件都只有一个凭据目录。`opencode` 有两个，需要两条 `-v` 行；`antigravity` 把令牌保存在操作系统的密钥环中，一条也不需要，改为在容器内登录；`aider` 绑定的是一个文件，并从环境变量读取模型密钥。你选择它们时，步骤中会有相应说明。

### 运行命令不会保留任何可能过时的东西 {#run-command}

`--pull=always` 会在每次启动时获取当前镜像，因此已经移动的配置文件标签无需你察觉就能到达你手中，而 `--rm` 意味着不会保留任何可能过时的东西。没有单独的“回头再用”路径——过去正是这一点让人运行着比所读页面旧了好几个月的 `motir`。你的登录状态不受这一切影响：它写入 `{{value:authVolume}}` 卷，该卷位于容器之外，所以只需登录一次，之后每次运行都会沿用——彻底退出登录用 `{{value:signOutCommand}}`。离线工作？去掉 `--pull=always`：它在每次启动时都会访问镜像仓库，所以没有网络时运行会失败，而不是回退到你已有的镜像。以上全都是运行命令的行为。开发容器（第 2a–2c 步）会一直保留创建它时所用的镜像，直到你拉取、通过 _Dev Containers: Open Folder in Container…_ 附加，并选择 _Dev Containers: Rebuild Container_。

### 下一步 {#what-next}

`motir run` 接收一个范围——一个工作项、一整个故事，或用 `sprint` 表示当前活跃的 Sprint。`motir auto` 则无人值守地清空就绪集合，一次处理一个工作项，提交到一个会话分支上。两者接受的每个参数都在 [{{value:cliPage}}](/docs/cli) 页面上。

## 它限制了什么——以及没有限制什么 {#confines}

在你依赖它之前值得读一读，因为这三项中有一项是例外，而不是保证。

- **文件系统——受限。** 容器内唯一的宿主机界面，是一个可写的 `/workspace` 和你的智能体自己的凭据（以只读方式挂载）。没有 Docker socket，没有其他宿主机绑定。
- **网络——开放，这是有意为之。** 每个智能体都需要它的提供商 API，每个被调度的工作项都需要 git 远程仓库，因此镜像限制的是文件系统的影响范围，而不是出站流量。如果你的威胁模型要求更多，请使用 Docker 自身的网络控制——容器不会阻止智能体访问互联网。
- **权限——无特权。** 它以 `node` 用户（uid 1000）运行，所以写入挂载目录的文件仍归你所有，而不是 root。

## 环境为你提供了什么 {#environment}

- **你的文件夹，已挂载。** `$PWD` 会变成 `/workspace`，所以运行所处理的仓库副本是你自己的，它产生的提交在退出时就在你的磁盘上。
- **每个工作项一份检出，位于 git 工作树上。** 一次运行不会编辑你当前所在的目录树；它会为每个工作项新增一个工作树，因此并行运行不会在分支检出上发生冲突。
- **你的智能体凭据，只读。** 配置文件的凭据目录以 `:ro` 绑定挂载。容器内没有任何东西能改写它，它的任何内容也不会发送给 Motir——这是自带密钥模式，所以智能体的费用由你承担，API 调用也不会经过我们。
- **预装的 CLI。** 镜像带有 `motir` 以及标签所指定的智能体二进制文件，所以首次运行前无需安装任何东西。
- **智能体的输出默认留在本地。** 只有运行的生命周期会到达 Motir。传入 `--report-log` 会额外发送输出的末尾部分，使失败的运行能在运行页面上显示它；除非你要求，否则它是关闭的，而且无论哪种情况，文件内容、路径和差异都不会被发送。

## 令牌可以做什么——以及它拒绝什么 {#token}

由 `motir login` 生成的令牌带有固定且收窄的授权。批准界面会显示它，但不能更改——既不能放宽也不能收窄，因为手动收窄的授权会让无人值守的循环在中途出错。

{{slot:grant}}

**它不带有的那个权限是 `ai:view_plan`，随之而来的拒绝是设计如此，而不是缺陷。** 打开计划只需要 `work_item:edit`，所以沙箱中的运行可以打开一个——然后在第一次追加时被拒绝，因为添加提案所校验的正是那个权限。执行某个工作项的运行无权重塑交给它的计划。遇到这个拒绝时，说明智能体做对了：它把更正记录为评论，让该工作项保持受阻，然后停止。不会丢失任何东西，由人来决定计划应该怎么写。

想让运行更安静时，有两个参数可以进一步收窄：`--disable-log-bug` 让智能体不再为它在别处发现的缺陷提交缺陷工作项（改为留评论），`--disable-replan` 让它不再为它判定有误的工作项提交重新规划（改为留评论并停止）。仅在 `motir auto` 上，`--auto-approve-replan` 走相反的方向：它会批准已提交的重新规划并继续循环，而不是停下来等你。

## 一次运行会产出什么，以及在哪里查看 {#produces}

- **一个分支和一个拉取请求**，位于该工作项涉及的每个仓库，由容器内用你的 git 凭据推送。
- **工作项上的一个链接。** 运行会声明每个拉取请求交付的是哪个工作项，所以合并它就会推进该工作项。工作项页面的“开发”面板显示的正是这个链接，在合并时关闭工作项的也是它——不是分支名，也不是标题。
- **状态，随进度更新。** 运行领取工作项时，它变为进行中；拉取请求打开时，它变为已实现。评审中由 CI 在检查通过时写入，已完成则由合并写入。
- **终端。** 除非你传入了 `--report-log`，否则智能体自己的输出会留在你的终端中。

## 它无法正常工作时 {#troubleshooting}

### 找不到智能体二进制文件 {#agent-binary-not-found}

标签与智能体不一致。检查你启动的是哪个配置文件，或用 `--agent <cmd>` 让运行指向另一个二进制文件。`motir doctor` 会在运行白白占用一次领取之前报告这一点。

### 智能体已启动，但未通过认证 {#agent-not-authenticated}

凭据挂载缺失，或指向了错误的目录——每个配置文件各自挂载自己的目录。请针对你实际拉取的标签，重新运行 `{{value:dockerRun}}` 那一行。

### 没有可运行的内容 {#nothing-ready}

每个候选项都有未满足的依赖。`motir ready` 会显示就绪集合；对某个工作项运行 `motir show`，会指出是什么阻塞了它。无论如何都要调度，则用 `--force`，且一次只能调度一个工作项。

### 运行因已提交的重新规划而停止 {#stopped-on-replan}

智能体判定该工作项有误，并提出了修正后的结构。这是预期的停止：请在 Motir 中阅读该计划，并批准或拒绝它。若想让无人值守的循环继续，请运行 `motir auto` 并加上 `--auto-approve-replan`。

### 运行退出后留下了未完成的工作 {#work-left-behind}

工作树和分支在你的磁盘上，位于你挂载的文件夹下——容器停止并不会把它们带走。`motir done` 会收尾一个已合并的工作项，或用 `--session <branch>` 收尾整个已合并的会话分支。
